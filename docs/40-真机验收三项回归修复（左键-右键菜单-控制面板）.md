# 40 · 真机验收三项回归修复（左键无反应 / 右键菜单不能滚 / 控制面板跑偏）

> 范围：**只修这三个回归**。未改 Android、未接任何业务动作、未进入增量 C。
> 前置：`docs/37`（Android 基准审计）、`docs/38`（增量 B 移植）、`docs/39`（固定画布按当前设置规划）。

---

## 0. 结论速览

| 回归 | 根因（可判定） | 修复落点 |
|---|---|---|
| ① 左键单击桌宠完全无反应 | `WheelMenuView` 的 `Ticker` 在**挂载**时不会启动（`initState` 只 `addListener`），且 `tick()` 在"首个 tick 已超时长"时**保留旧帧** → `openProgress` 永远停在 `0` → 画笔 `if (openProgress <= 0.004) return` 整帧不画。Region 其实已经扩开了，所以表现为"点了没反应"。 | `wheel_menu_view.dart`（`_syncTicker` 挂载即同步 + `tick()` 无条件取 `WheelAnimationClock.frame`） |
| ② 右键旧菜单一次性展开、超出高度且不能滚 | `showMenu` 的默认 `constraints` **只有 minWidth / maxWidth、没有 maxHeight**，把 popup route 自带的"overlay − 8px"高度约束覆盖掉 → 内部 `SingleChildScrollView` 拿到**无限高**。 | 新增 `menu/context_menu_layout.dart` + `ui/desktop/pet_context_menu_overlay.dart`，用受约束 `OverlayEntry` 取代 `showMenu` |
| ③ 控制面板离桌宠 / 屏幕有效区较远 | `commitPanelBounds` 用 `windowController.position()`（= **当前窗口**左上角 = 固定画布左上角 = `petScreen − petAnchor`）当面板位置，再被夹取推到屏幕角落。 | 新增 `ui/desktop/panel_layout.dart`，按**桌宠所在显示器 workArea** 居中 + 尺寸适配 |

附带修掉两个**同源缺陷**（不做会立刻再犯）：

* `A WheelMenuController was used after being disposed.` —— 控制器先销毁、`Ticker` 的 tick 发生在下一帧 build 之前；
* **面板位置被写进桌宠位置** —— 面板 `SetWindowPos` 触发 `onWindowMoved` → `_commitPosition`，而进入面板时 `fixedCanvasAnchor` 已被清掉，于是"面板左上角"被当成桌宠位置持久化。

| 3 | `pet.tap.recognized` | `PetView` 的 `onTap` 包装 | 单击被手势识别 |

| 5 | `wheel.toggle.request` | `FixedCanvasProbeState.toggleFormalWheel()` | 正式轮盘统一入口被调用（带 gate / menuOpen / fallback / passthrough / rebuilding / diagnosticMenu） |
| 6 | `wheel.state` | `WheelInteractionGate._transition` | 四态机迁移（from / state / reason / seq） |

### 1.2 逐层确认（代码位置 → 结论）

| # | 检查项 | 落点 | 结论 |
|---|---|---|---|
| 1 | `PetView.onTap` 是否触发 | `pet_view.dart` `GestureDetector.onTap` | ✔ 触发（并落 `pet.tap.recognized`） |
| 2 | `PetViewWrapper` 是否传递 | `pet_view_wrapper.dart` `onTap: onPetTap` | ✔ 直传 |
| 3 | `DesktopShell` 是否收到 | `_PetWindowMode.onPetTap` | ✔ 收到（落 `desktop.pet_tap.received`） |
| 4 | 探针（正式轮盘宿主）是否收到 | `toggleFormalWheel()` | ✔ 收到（落 `wheel.toggle.request`） |
| 5 | `WheelInteractionGate` 是否允许 | `_gate.beginOpen()`（closed 才放行） | ✔ 允许；opening/open 时第二次点击记 `wheel.reentry_ignored` |
| 6 | `RegionCoordinator` 是否授予 `wheel` | `_coordinator.apply(owner: wheel, ...)` | ✔ 授予（`wheel.region.acquire.result.success = true`） |
| 7 | `WheelUiState` 是否 closed → opening | `_gate.completeOpen()` + `wheel.phase` | ✔ `opening` → 动画收敛后 `open` |

| 9 | 正式轮盘 Widget 是否进树可见 | `build()` 里 `WheelMenuView` | ✔ 进树；且关闭态用 `IgnorePointer` 明确让开命中 |

### 1.3 根因（两层，都在装配层）

```
open() 顺序：… _gate.completeOpen() → setInteractive(true) → beginOpenAnimation() → setState()
                                                                    ↑ 记下 startedAtMs
setState 之后才 build → WheelMenuView.initState → 旧代码只有 addListener（无通知）
   ⇒ _syncTicker() 从未被调用 ⇒ Ticker 不启动 ⇒ tick() 从不执行
   ⇒ _frame 停在 prepareContent 的 openProgress = 0
   ⇒ _WheelPainter.paint 第一行 `if (controller.frame.openProgress <= 0.004) return;`
   ⇒ 整帧什么都不画（Region 已扩开，所以"点了没反应"）
```

第二层（修第一层后才显形）：

```
若首个观测到的 tick 已经超过动画时长，旧 tick() 走 `isFinished ? _frame : frame(...)`
   ⇒ 保留旧帧 ⇒ 依旧停在 0；正确做法是取 frame()（内部 clamp ⇒ 得终态 1.0）
```

修复：

```dart
// initState / didUpdateWidget：主动同步一次
_syncTicker();

// tick()：无条件取当前时刻的帧（clamp 到 [0,1]，因此天然包含终态）
next = WheelAnimationClock.frame(active, now);
```

并且顺手修掉同源的 `used after being disposed`：`WheelMenuController` 增加 `_disposed`，
`tick()` 在已销毁时 no-op（Ticker 的 tick 在 build **之前**，而 Widget 要到本帧 build 才出树）。

## 2. 左键：手势遮挡与层级

绘制层级（自下而上）与输入层级**分开**：

```
视觉：menu painter → menu buttons → (Region 可视化) → pet            // 桌宠始终在最上
输入：closed / closing  → 只有 pet 可交互
      opening / open / switching / enteringLayer / exitingLayer → pet + 实际菜单 Region
      透明画布 → 永不可交互（Region 只含 pet ∪ 菜单几何）
```

`WheelMenuView` 的加固（真机验收要求逐条对应）：

| 要求 | 实现 |
|---|---|
| `IgnorePointer(ignoring: …)` | `build()` 顶层包 `IgnorePointer(ignoring: phase == closed \|\| phase == closing)` |
| 不用全画布 `HitTestBehavior.opaque` | `CustomPaint` + `SizedBox.expand()`，未设 opaque |
| 不用透明 `GestureDetector` 覆盖桌宠 | 只用 `Listener`（`deferToChild`）+ `MouseRegion` |
| 不参与命中测试（closed） | 上面的 `IgnorePointer` |
| 只在 open 类状态接收输入 | 阶段判定 + `controller.setInteractive(true)` 双门控 |

**测试证据**：`test/pet_tap_wheel_chain_test.dart` 用"轮盘层盖在记账手势层之上"验证
closed / closing 时点击落到下层、opening 时被轮盘接管。

## 3. 左键：入口接线纪律（不再指向旧探针）

`DesktopShell` 的 `onPetTap` **只允许**调用 `FixedCanvasProbeState.toggleFormalWheel()`：

* ✘ 六色块诊断菜单（`legacyTestMenu`）—— 它只是**渲染开关**，不是入口；
* ✘ `dynamicSetBoundsProbeEnabled`（已标记 rejected 的旧探针）—— 不再引用 `WheelGeometryProbe`；
* ✘ "只改诊断状态、不改变正式 `WheelUiState`" 的旧 toggle；
* ✘ 直接裸写 Region。

正确打开顺序（`open()` 内，顺序即代码顺序）：

```
1. closed → opening（首个 await 之前，同步）        _gate.beginOpen()
2. 计划过期 → 关闭态原子重建一次画布（如需要）      _rebuildFixedCanvas('plan-stale-before-open')
3. 取显示器 + 在屏幕坐标算 Android 对齐信封         WheelMenuGeometry.computeEnvelope
4. 准备内容 + 正式菜单进树                          wheel.prepareContent(...) / setState
5. 右键事务失效 + 等 popup 关闭                     invalidateOwner(contextMenu) / dismissAndWait
6. Region 申请（owner = wheel）                     wheel.region.acquire.start / .result
7. setInteractive(true)
8. beginOpenAnimation()
9. 动画完成 → root（phase = open）
```

失败时：`_fallbackToSmallWindow` + `_showMessage('窗口 Region 应用失败，已回退小窗口模式：…')` +
`_gate.failOpen()`，Region 收敛到 pet —— **不静默、不留大透明块**。

**测试证据**：条文扫描断言 `onPetTap` 块包含 `toggleFormalWheel`、不含 `WheelGeometryProbe` /
`legacyTestMenu` / `setWindowRgn`；`toggleFormalWheel` 与 `toggle` 是同一实现（薄封装）；
探针 `#17` 断言连续两次左键只产生一个事务。

## 5. 右键菜单：workArea 约束 + 可滚动 + 键盘 + Region 精确

### 5.1 为什么必须换掉 `showMenu`

Flutter `popup_menu.dart` 的模态项内部：

```dart
final Widget child = ConstrainedBox(
  constraints: widget.constraints ?? const BoxConstraints(minWidth: 2*56, maxWidth: 5*56),
  … child: SingleChildScrollView(…) …);
```

默认 `constraints` **没有 maxHeight**，直接覆盖掉 `_PopupMenuRouteLayout`
计算出的"overlay − 8px"。于是滚动容器拿到无限高 → 全部条目摊开、超出屏幕、不能滚。
（键盘导航在 `showMenu` 里也没有实现，`FocusTraversalGroup` 都没用到。）

### 5.2 新实现

`menu/context_menu_layout.dart`（纯几何，**规划值 == 最终渲染值**）：

```
maxHeight = min(workArea.height - 32, 560)
maxWidth  = min(workArea.width  - 32, 360)
width     = clamp(preferredWidth, minWidth 200, maxWidth)
height    = min(contentExtent, maxHeight)
位置      = 锚点右下 → 放不下翻左上 → 夹进 workArea ∩ overlay（各侧再内缩 8px）
itemExtent = 40     dividerExtent = 9     verticalPadding = 8
```

`ui/desktop/pet_context_menu_overlay.dart`（受约束 `OverlayEntry`）：

* `Material` + `ConstrainedBox(maxHeight, maxWidth)` + `SingleChildScrollView` → **高度有限 ⇒ 能滚**；
* 墨迹层之外整屏透明 `GestureDetector(opaque)`：点击外部关闭（等价 `showMenu` 的 barrier）；
* `Focus(onKeyEvent)`：`Esc` 关闭、`↑↓` 移动高亮（跳过只读 / 分隔线）、`Enter` / `Space` 激活；
* 打开时把"当前状态"项滚入可见区（`initialScrollOffset`）；
* `onPresented` 交出"主动关闭"句柄 → 仍接在 `ContextMenuBridge` 上（外壳切面板前能 dismiss 并等待）。

### 5.3 Region 只覆盖实际菜单矩形

`ContextMenuRegionPort.expand()` → `expandTo(Rect menuLocalRect)`；探针提交
`pet ∪ 菜单矩形`（**不再** `Offset.zero & _canvas` 整块画布），关闭后按凭据 `restoreIfCurrent`
回到 pet-only。`wheel > contextMenu` 优先级不变，轮盘开着时右键直接拒（`context_menu.rejected`）。

### 5.4 逐条验收对应

| 要求 | 实现 | 测试 |
|---|---|---|
| 1 anchor 用鼠标坐标 | `onSecondaryTapDown` 的 `globalPosition` → overlay 局部 | `context_menu_anchor_test` + 规划测试 |
| 2 取鼠标所在显示器 workArea | 外壳注入 `displayForPoint` | 12b / 12c |
| 3 `maxHeight = workArea.height - 上下安全边距` | `maxHeightFor()`（−32，上限 560） | 9 / 9b |
| 4 合理 maxWidth | `maxWidthFor()`（−32，上限 360，下限 200） | 9 |
| 5 内容可滚动容器 | `SingleChildScrollView` + 有限高 | 10 / 10d |
| 6 打开时当前状态项滚入可见 | `ensureVisibleOffset` | 10c |
| 7 鼠标滚轮可滚 | 原生 `Scrollable` | 10d（真实 `PointerScrollEvent`，断言 offset 增大） |
| 8 上下键移动选择 | `_onKey` + `nextActionable` | 11 / 11c |

## 6. 控制面板：按桌宠所在显示器居中

`ui/desktop/panel_layout.dart`（纯函数）：

```
width  = min(1180, workArea.width  - 32)
height = min(760,  workArea.height - 32)
left   = workArea.left + (workArea.width  - width ) / 2
top    = workArea.top  + (workArea.height - height) / 2
```

外壳 `openPanel()` → 先算尺寸（事务的尺寸校验用同一个值），`commitPanelBounds()` → 一次 `SetWindowPos`。

| 要求 | 实现 |
|---|---|
| 1 取进入前的 `petScreenRect` | `_petScreenRectNow()`（画布矩形 + `petAnchor`，失败退保存值） |
| 2 用 `petScreenRect.center` 选显示器 | `_workAreaForPetScreenAsync` |
| 3 取该显示器 workArea | `displayForPoint(center)` |
| 4 尺寸适配（1180×760 → `min(…, workArea-32)`） | `PanelLayout.sizeFor` |
| 5 在目标 workArea 中居中 | `PanelLayout.centeredIn` |
| 6 完整位于 workArea（不"靠近宠物"而越界） | `centeredIn` + 事务校验 `isBoundsFullyVisible` |
| 7 一次 setBounds 提交位置 + 尺寸 | `commitPanelBounds`（唯一提交点） |
| 8 清除 Region 后再显示 | `enterPanel` 第 5 / 8 步 |
| 9 回读 actualBounds 并确认完整可见 | 第 12 / 13 步（`isBoundsFullyVisible`） |
| 10 不把面板位置写入桌宠位置 | `windows_window_controller._commitPosition` 增加 surface 模式守卫 + `app_scope.shutdown` 同守卫 |
| 11 返回桌宠继续用进入前捕获的位置 | `_panelReturnPetScreen` → `commitFixedCanvasBounds` |

**不再使用**：固定画布窗口左上角 ✘、`petAnchor` 局部坐标 ✘、旧 `_contentWidth/_contentHeight` ✘、
"默认显示器" ✘（旧 `_clampPanelRect` 已删除）。

1. **面板仍是同一个 HWND**（不是独立窗口）：进入面板时窗口矩形从"画布"变成"面板"，
   这是既有架构（阶段 0 验收口径），本轮只改**位置口径**，不改多窗口方案。
2. **"面板中心略靠近宠物"未做**：要求 §6.6 是"可让"，实现选择**严格居中**——
   居中是最可判定、且一定能完整落在 workArea 内的方案；若后续要"体现来源"，
   在 `PanelLayout.centeredIn` 上加一个受工作区夹取的偏移即可（不新增常量）。
3. 菜单快捷键只实现 `Esc / ↑ / ↓ / Enter / Space`；`showMenu` 时代也**没有**键盘导航，
   因此这是纯增量，不构成回归。
4. 右键菜单宽度上限 360 是**估算量**（文本量测 + 图标槽 + 左右内边距），
   极端长文案会走 `TextOverflow.ellipsis`。
