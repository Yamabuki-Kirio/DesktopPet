# 41 · 启动位置语义统一与可见性保护（真机回归：桌宠不可见）

> 范围：**只修启动位置语义与可见性保护**。未改 Android、未接业务动作、未进入增量 C。
> 前置：`docs/38`（增量 B 移植）、`docs/39`（画布按当前设置规划）、`docs/40`（上一轮三项回归）。

## 0. 结论速览

真机日志给出的链条：

```
位置加载 (-300, 307)
  → 旧小窗口路径 moveTo(-300,307)，按 256×192 夹取后临时放到 (1640, 824)   ← 只改了 HWND
  → 固定画布初始化**重新读旧设置** (-300, 307) 当 petScreenPosition
  → 画布矩形 (-633, 13, 922×844)、人物矩形 (-300, 307, 256×256)
  → 人物与显示器 [0,1920] 交集 = 0（完全在屏外）
  → 但旧的可见性判据检查的是**画布矩形**（289×844 相交 ≥ 48px）→ 判"够了"
  → show()，日志写"桌宠显示"，人物实际不可见
```

四个根因（与用户判断一致，逐条确认）：

| # | 根因 | 落点 |
|---|---|---|
| 1 | 旧 `WindowsWindowController` 把 `settings.windowX/Y` 当**窗口左上角** | `applySettings` → `moveTo(x, y)` |
| 2 | 固定画布把同一对字段当 **`petScreenPosition`** | `prepareFixedCanvas` → `savedPetScreenPosition()` |
| 3 | 旧位置检测只修**临时小窗口**，既不修 `settings` 也不修画布启动事务用的锚点 | `DisplayTopology.clamp` 只作用于 `moveTo` 的 HWND |
| 4 | 画布随后重新使用旧负坐标 → 人物锚点落到屏幕外；且 `_clampCanvas` 校验的是**画布**不是**人物** | `_clampCanvas` 的 `minVisible = 48` 看 `rect`（画布） |

修复后：**语义唯一（v2 = `petScreenPosition`）**、启动路径**只有一条**、校验对象是**人物矩形**、
`(-300,307)` 被判不可见并**迁移到主屏右下角**且立刻写回 v2。

## 1. 唯一位置语义

`lib/menu/pet_position_resolver.dart`（新增，**纯 Dart**，可在 `flutter_tester` 单测）：

```dart
abstract final class WindowPositionSchema {
  static const int v1 = 1;       // 旧语义：窗口左上角
  static const int v2 = 2;       // 当前语义：petScreenPosition（人物可见区域左上角）
  static const int none = 0;     // 历史数据：无版本
  static const int current = v2;
  static bool isPetScreenPosition(int version) => version == v2;
}
```

`AppSettings` 新增字段 `windowPositionSchema`：

* 序列化键 `window.positionSchema`（与既有 `window.x` / `window.y` 并列）；
* 缺省 = `none`（历史数据）→ 启动按"语义不确定"处理；
* `AppSettings.normalized()` 不改它（迁移只能由解析器决定）。

**写入侧**：`SettingsController.rememberWindowPosition()` **总是**写 `v2`。
专门保留 `rememberWindowPositionWithSchema(...)` 给启动迁移 / 修正用（显式传版本）。

## 2. 启动流程（唯一顺序）

`FixedCanvasProbeState.prepareFixedCanvas()` 重写为 12 步，逐条对应需求：

| 需求步骤 | 实现 | 诊断日志 |
|---|---|---|
| 1. 窗口保持隐藏 | 由 `WindowsWindowController.initialize` 保证（固定画布模式不 `show()`） | — |
| 2. 加载保存位置 + schema | `widget.savedWindowPosition()` | `startup.position.loaded` / `startup.position.schema` |
| 3. 加载素材 → 实际可见尺寸 | `widget.petSize()` | `startup.pet_size.ready` |
| 4. 解析 `savedPetScreenPosition` | `PetPositionResolver.resolve(...)` | `startup.pet_position.validated` |
| 5. 校验**人物可见矩形** | `visibleRatio(petRect, workArea) ≥ 0.5` | 同上（带 `petRect` / `visibleRatio` / `targetDisplayId`） |
| 6. 不可见 → 修正 + **立刻持久化 v2** | `persistPetScreenPosition(...)` | `startup.pet_position.corrected` / `startup.position.migration` |
| 7. 算 canvasPlan + petAnchor | `_planCanvas(...)` | `startup.canvas_plan.ready` |
| 8. `canvasWindowPosition = petScreenPosition − petAnchor` | `PetWindowPosition.windowFromPetScreen` | — |
| 9. **一次** `commitBounds` | 唯一提交点 | `startup.canvas_bounds.commit`（带 `count: 1`） |
| 10. 应用 pet-only Region | `_coordinator.apply(owner: pet, ...)` | `startup.region.applied` |
| 11. 等布局 | 见 §5「不等待帧」的说明 | — |
| 12. 回读 + 校验人物可见 | `currentBounds()` + 重新算 `visibleRatio` | `startup.actual_window_rect` / `startup.actual_pet_screen_rect` / `startup.pet_visible_ratio` |
| 13. 达标才 show | `_startPetMode` 拿到 `true` 才 `setVisible(true)` | `startup.window.show` |

**禁止项已逐条落实**：

| 禁止 | 落实 |
|---|---|
| 先把小窗口移到右下角 | `applySettings` 在固定画布模式下**整体**跳过旧位置 + 旧尺寸写入，并记 `startup.legacy_move_skipped` |
| fixed canvas 又读旧设置 | 启动只经 `PetPositionResolver`；修正后的值进内存并写库，旧值不再被读 |
| show 后才发现人物不可见 | return false → 外壳走安全回退，**不 show** |
| 仅记录 show 成功而不校验可见性 | `startup.window.show` 只在 `visibleRatio ≥ 0.5` 之后记录，且带 5 个必需字段 |

`startup.window.show` 的字段（用户 §7 要求）：

```
actualWindowRect / actualPetScreenRect / targetDisplayId / visibleRatio / regionBoundingBox
（另附 regionRects 计数）
```

## 3. 历史位置迁移

`PetPositionResolver.resolve()` 的决策表：

| 输入 | 处理 | `source` |
|---|---|---|
| 无保存值 | 主屏右下角默认位置 + 写 v2 | `first_run` |
| v2 且可见（≥50%） | **原样使用**，不写库 | `v2` |
| v2 但不可见 | 主屏右下角默认位置 + 写 v2 | `corrected_invisible` |
| v1 / 无版本 + `legacyWindowSize ≈ petVisibleSize` | 窗口左上角**等价**人物左上角 → 直接转换 + 写 v2 | `migrated_v1_exact` |
| v1 / 无版本，语义无法确定 | **不猜测** → 主屏右下角默认位置 + 写 v2 | `migrated_v1_unknown` |

* 迁移**只执行一次**：`needsPersist` + 外壳 `persistPetScreenPosition` 立刻写库，
  本次会话此后只用内存里的修正值；
* 不改变 Android 设置（解析器是纯 Dart、平台中立，Android 侧完全不接这条链）；
* 真机案例 `(-300, 307)` + 单屏 1920×1040 → `migrated` 判定为 `corrected_invisible`，
  修正为 **(1632, 752)**（= 右下角 − 32px 安全边距），并立刻写 v2。

旧窗口尺寸的判定：v1 时代没有固定画布，窗口矩形 == 素材尺寸 × 缩放，
因此 `legacyWindowSize` 就是当前 `petLogicalSize`；只有它 ≈ 人物尺寸时才允许直接转换。
（`DesktopShell.legacyWindowSizeForMigration` 把这个前提显式写进代码。）

## 4. 位置保存

`SettingsController.rememberWindowPosition()` 是唯一写入口，保存公式：

```
petScreenPosition = fixedCanvasWindowPosition + petAnchor
```

`lib/menu/pet_position_resolver.dart` 的 `PetWindowPosition`：

```dart
static Offset petScreenFromWindow({required Offset windowPosition, required Offset petAnchor});
static Offset windowFromPetScreen({required Offset petScreenPosition, required Offset petAnchor});
```

（互为逆运算，单测覆盖。）

保存时机（全部已接）：

| 时机 | 落点 |
|---|---|
| 用户拖动桌宠结束 | `WindowsWindowController._commitPosition`（`pos + petAnchor`），已带 surface 模式守卫 |
| 托盘「重置位置」 | `DesktopShell.resetPetPosition` |
| 切换显示器后完成夹取 | `_rebuildFixedCanvas` → 下次 `rememberWindowPosition`（拖动 / 退出） |
| 正常退出 | `AppScope.shutdown`（**带 surface 模式守卫**） |
| 固定画布重建成功后 | `rebuildFixedCanvasAt` / 启动迁移 |

**禁止保存**的东西都有对应守卫：

* 固定画布左上角 —— 一律 `+ petAnchor` 换算后写；
* 控制面板左上角 —— `windowsSurfaceSession.mode != petFixedCanvas` 时 `_commitPosition` 直接 return（记 `pet.position.commit_skipped`），`shutdown` 同理（记 `pet.position.save_skipped`）；
* Region 包围盒左上角 —— 该值从不参与位置保存。

`panel` / `transitioningToPanel` / `transitioningToPet` 模式下**都不**会覆盖桌宠位置。

## 5. 关于 `endOfFrame`：一个必须记录的实现决定

启动事务与 `rebuildFixedCanvasAt` **不再** `await WidgetsBinding.instance.endOfFrame`。

原因（实测）：`endOfFrame` 依赖后续帧；当这些事务被**直接 `await`**（外壳启动、托盘重置；
或 `flutter_tester` 里没人 `pump`）时会**永久挂起**。修 `prepareFixedCanvas` 时先踩到的就是它
（单测 4 分钟不返回）。`Future.timeout` 也救不了 —— 定时器在 `testWidgets` 的假时钟里不自行触发。

替代：`await Future<void>.microtask(() {})`（一次事件循环让位）。

**为什么安全**：pet-only Region 的矩形完全由 `petAnchor` + 人物尺寸推出（纯几何），
与 Flutter 布局无关；而"窗口矩形已提交"这件事由随后的 `currentBounds()` 回读**证实**，
不依赖帧。真正的"布局完成"由外壳 `setVisible(true)` 之后的正常运行自然满足。

`_rebuildFixedCanvas`（面板返回 / 设置变更）保留 `endOfFrame` —— 它由 `pumpAndSettle` /
真实事件循环驱动，不会挂起，且那条路径确实需要布局收敛。

## 6. 托盘「重置位置」

`AppScope` 旧实现 `moveTo(0, 0)` 已删除（单测条文扫描钉死）。改为：

```
AppServices.resetPositionHook → DesktopShell.resetPetPosition()
  1. 算主显示器上的默认 petScreenPosition（右下角 + 32px 安全边距）
  2. 先写 v2（重建事务会读它）
  3. probe.rebuildFixedCanvasAt(target, reason: 'tray.reset_position')
       保持隐藏 → 重算计划 → 一次 commitBounds → 反推 petAnchor
       → pet-only Region → 回读校验人物可见
  4. 通过 → setVisible(true) + 记 tray.reset_position.done（带 show 证据）
     失败 → _startupSafeFallback('tray_reset_failed')
```

`rebuildFixedCanvasAt` 与 `_rebuildFixedCanvas` 的差别：后者**保持人物屏幕位置不变**（只换画布尺寸），
前者**要**改人物位置，因此合并成"移动到目标 + 重建"的单一事务。

## 7. 启动可见性保护

`DesktopShell._startupSafeFallback(reason)`，触发条件：

* 画布初始化失败（`prepareFixedCanvas` 返回 false）；或
* Region 应用失败 / Region 为空；或
* 人物矩形完全不在任一显示器；或
* 人物可见面积 < 50%。

动作：清 Region（owner=panelTransition）→ `releaseFixedCanvas`（清 `petAnchor`）→
`resizeTo(pet)` → `moveTo(主屏右下角)` → 写 v2 → `setVisible(true)` → 桌面提示
「桌宠位置数据异常，已回到屏幕右下角（原位置不可见）」。托盘与退出入口不受影响。

日志：`startup.safe_fallback`（带 reason / mode / pet 尺寸）。

## 10. 立即可用的人工验收（用户 §9）

1. 人为写入无效位置 `(-300, 307)`（`settings` 表 `window.x` / `window.y`，并把 `window.positionSchema` 置 2）。
2. 启动 → 桌宠应出现在**主屏右下角**（1920×1040 上是 `1632, 752`）。
3. 日志必须有 `startup.pet_position.corrected` 与 `startup.pet_visible_ratio`（`ok: true`）。
4. 完全退出重启 → 仍在正确位置（因为已写回 v2）。
5. 拖动后退出重启 → 位置保持。
6. 打开控制面板再返回 → 位置保持（`pet.position.commit_skipped` 不应在桌宠态出现）。
7. 托盘「重置位置」→ 立即出现并持久化。
8. 左键轮盘、右键菜单、双击面板继续正常（`docs/40` 的回归用例全绿）。

## 11. 已知限制

1. **迁移判定依赖"v1 窗口尺寸 == 人物尺寸"**：本项目 v1 时代窗口尺寸就是素材×缩放，
   因此该前提成立。若将来出现"窗口尺寸与人物尺寸不同的 v1 数据"，
   会被判为语义不明并回退默认位置（宁可重置也不猜测）。
2. **可见性阈值 0.5**：用户只写"规定比例"。取 0.5（至少一半在屏内）。
   它比旧 `moveTo` 的"任一侧 ≥48px"（256px 人物 ≈ 19%）严格，能拦住"只剩一条边在屏内"的坏数据；
   副作用是"用户主动把桌宠拖到只剩三分之一在屏内"的位置，下次启动会被修正回右下角。
3. **启动不等待帧**（§5）：若未来有人依赖"show 之前 Flutter 已完成布局"，需要重新引入
   **由调用方驱动**的帧等待（例如外壳在 `setVisible` 前主动 `endOfFrame`），而不是在事务内部 await。
4. **单屏 vs 多屏的默认位置**：默认位置取**主显示器**右下角。若用户桌宠长期在副屏，
   坏数据修正后会回到主屏（这是"可见性优先"的取舍，已在 `PetPositionResolver` 注释里写明）。
