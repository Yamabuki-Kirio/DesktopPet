# 16 · 服务端部署与配置

> 适用于 `server/`。所有命令都在 `server/` 目录下执行。

## 1. 本机实测环境（无 Docker / 无 PostgreSQL 时也能跑）

本机**没有** Docker、PostgreSQL，也没有系统 Python。为了能真实运行与测试服务端，
项目内下载了 Python 官方 **embeddable 包**（免管理员、不改系统、可直接删除）：

```
server/.python/                 ← 本地 Python 3.12.10（约 11 MB，已在 .gitignore 中排除）
server/.python/python312._pth   ← 已加入 ".."，使 server/ 内的 app 包可导入
```

`.python/python312._pth` 内容（关键是把 `server/` 加进 sys.path）：

```
python312.zip
.
..
import site
```

> embeddable 发行版会**忽略脚本所在目录**，所以必须显式把 `..` 写进 `._pth`，
> 否则 `import app` 会报 `ModuleNotFoundError`。

初始化方式（可复现，仅需一次）：

```powershell
# 1) 下载并解压
Invoke-WebRequest -Uri https://www.python.org/ftp/python/3.12.10/python-3.12.10-embed-amd64.zip -OutFile py.zip
Expand-Archive py.zip -DestinationPath .python -Force

# 2) 打开 site 并加入 server/ 到 sys.path（把 python312._pth 改成上面 4 行）

# 3) 引导 pip 并安装依赖
Invoke-WebRequest -Uri https://bootstrap.pypa.io/get-pip.py -OutFile get-pip.py
.python\python.exe get-pip.py --no-warn-script-location
.python\python.exe -m pip install -r requirements.txt -r requirements-dev.txt
```

### 1.2 一个必须记住的坑：`PYTHONUTF8=1`

`alembic.ini` 由 configparser 以 `encoding="locale"` 读取。zh-CN Windows 的
locale 编码是 **GBK**，因此：

- ini 文件里的**非 ASCII 注释**会让 alembic 在建连前就抛
  `UnicodeDecodeError: 'gbk' codec can't decode byte ...`；
- 中文日志写入重定向文件时也可能抛 `UnicodeEncodeError`。

对策（两条都做了）：

1. `alembic.ini` **保持纯 ASCII**（并有测试断言）；
2. 运行服务端命令时设置 `PYTHONUTF8=1`。Dockerfile 里也固定设置了它。

## 2. 快速开始

### 2.1 本机（SQLite，已实测）

```powershell
$env:PYTHONUTF8='1'
$env:PETLIFE_JWT_SECRET='<48 字节随机串>'
$env:PETLIFE_DATABASE_URL='sqlite+pysqlite:///./petlife_server_dev.db'

.python\python.exe -m alembic upgrade head          # 建表
.python\python.exe -m uvicorn app.main:app --port 8000
```

验证：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
# status=ok  database=True  version=0.2.0
```

### 2.2 Docker Compose（含 PostgreSQL）

```bash
cd server
cp .env.example .env
python -c "import secrets;print(secrets.token_urlsafe(48))"   # 填进 PETLIFE_JWT_SECRET
# 设置 POSTGRES_PASSWORD（不设置 compose 会直接失败，杜绝默认弱口令）

docker compose up --build
```

compose 定义的三个服务：

| 服务 | 作用 |
|---|---|
| `db` | PostgreSQL 16，数据落命名卷 `petlife_pgdata` |
| `migrate` | 一次性容器，执行 `alembic upgrade head`，成功后退出 |
| `api` | uvicorn；`depends_on: migrate (service_completed_successfully)`，确保**先迁移再起服务** |

只跑迁移：`docker compose run --rm migrate`
停止（保留数据）：`docker compose down`
停止并删数据：`docker compose down -v`

## 5. 配置项

见 `.env.example`。环境变量前缀统一为 `PETLIFE_`。

| 变量 | 默认 | 说明 |
|---|---|---|
| `PETLIFE_APP_NAME` | `PetLife API` | OpenAPI 标题 |
| `PETLIFE_ENVIRONMENT` | `development` | `production` 时关闭 `/docs` 与 `/openapi.json` |
| `PETLIFE_DATABASE_URL` | `sqlite+pysqlite:///./petlife_server_dev.db` | 支持 PG / SQLite |
| `PETLIFE_DATABASE_ECHO` | `false` | 打印 SQL（排查用） |
| `PETLIFE_JWT_SECRET` | **必填** | 少于 16 字符或为占位值（`change-me` 等）会**启动失败** |
| `PETLIFE_JWT_ALGORITHM` | `HS256` | |
| `PETLIFE_ACCESS_TOKEN_TTL_MINUTES` | `15` | 需求建议 15 分钟 |
| `PETLIFE_REFRESH_TOKEN_TTL_DAYS` | `30` | 需求建议 30 天 |
| `PETLIFE_JWT_ISSUER` | `petlife` | 校验 `iss` |
| `PETLIFE_ARGON2_TIME_COST` | `3` | Argon2id 迭代次数 |
| `PETLIFE_ARGON2_MEMORY_COST` | `65536` | 64 MiB |
| `PETLIFE_ARGON2_PARALLELISM` | `4` | |
| `PETLIFE_SYNC_MAX_BATCH_SIZE` | `200` | 单批上限（超出返回 413） |
| `PETLIFE_SYNC_PULL_MAX_ITEMS` | `500` | 每类每次拉取上限 |

`docker-compose.yml` 额外读取：`POSTGRES_DB`、`POSTGRES_USER`、
`POSTGRES_PASSWORD`（**必填**）、`API_BIND_ADDRESS`（默认 `127.0.0.1`，只监听本机）、
`API_HOST_PORT`。

### 5.1 客户端如何配置服务端地址

客户端把服务端地址存本地（`account_session.server_base_url`），UI 上可修改：

- 开发：`http://127.0.0.1:8000`
- 局域网：`http://<内网IP>:8000`
- 生产：`https://api.example.com`（**必须 HTTPS**，否则 Bearer 令牌在链路上明文传输）

服务端不内置任何真实地址，也不会主动对外发起连接。

## 6. 数据库结构由迁移唯一负责

`app/main.py` **不调用** `create_all`。这样做是为了避免经典事故：
开发环境用 `create_all` 建表、生产用迁移建表，两者结构悄悄漂移，
表现为「本地好好的，上线就缺列」。

`test_migrations.py` 会真实执行迁移，并逐项比对迁移结果与模型声明
（表 / 列 / 主键 / 外键 / 唯一约束 / 索引），把这种漂移挡在 CI 里。

## 7. 生产部署清单

1. **HTTPS**：Caddy/Nginx 终止 TLS，compose 的 `API_BIND_ADDRESS` 保持 `127.0.0.1`。

   ```
   api.example.com {
       reverse_proxy 127.0.0.1:8000
   }
   ```

2. **密钥**：`PETLIFE_JWT_SECRET` 用 48 字节随机串，权限 600 的 `.env` 或密钥管理服务。
3. **轮换 JWT 密钥**：改 `.env` → `docker compose up -d api`。
   Access Token 全部失效（≤15 分钟后自动恢复），Refresh Token 在库里不受影响。
4. **备份**：

   ```bash
   docker compose exec db pg_dump -U petlife -Fc petlife > petlife_$(date +%F).dump
   docker compose exec -T db pg_restore -U petlife -d petlife --clean < petlife_2026-09-27.dump
   ```

5. **轮换数据库口令**：改 `.env` 的 `POSTGRES_PASSWORD` 后同步执行
   `ALTER USER petlife WITH PASSWORD '新口令';`
6. **不要在没有服务器地址与授权的情况下把本服务暴露到公网。**
   本仓库不会自动部署任何东西。
