## 2. 审计发现（修复前）

1. **Windows 开段失败会永久丢段**：`_openSegment()` 插入失败只记日志，之后 `_flush()` 只会更新秒数，不会补插入；该段永远不会出现在本地库/同步队列。
2. **Windows 关段失败会丢结束状态**：`_closeOpen()` 在数据库更新前就把 `_open` 置空，更新失败后结束时间、原因和秒数全部丢失。
3. **Windows 每个 tick 各自取整**：`activeMs ~/ 1000`、`idleMs ~/ 1000` 每个采样周期都丢弃不足 1 秒的余数，长期持续少算。
4. **Windows 跨午夜归属错误**：`_ensureDay(sample.wallNow)` 在结算 credit 之前切到新日，跨午夜的那一段被整段记到新日，旧日缺数据。
5. **Windows 最后活跃时间偏晚**：即使采样后半段已经空闲，`lastActiveAt` 仍写成采样结束时刻。
6. **Android journal 写失败直接丢记录**：`flushCompleted()` 写失败只打日志，已结束会话随内存状态一起丢失。
7. **Android 设备标识不一致会被自动确认/删除**：原逻辑把非本机记录从 journal 删除，可能永久抹掉真正的外部记录。

## 3. 修复后行为

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| Windows 开段插入失败 | 段只存在内存，永不再落库 | 保留 `_open` 并标记未持久化；下次 `_flush()` 先幂等补插，成功后才写 outbox |
| Windows 关段更新失败 | `_open` 被清空，结束状态丢失 | 保留待关闭状态（结束时间/原因/秒数）；下次 `_flush()` 优先补写关闭，成功后清检查点、通知同步、清内存 |
| Windows 1999ms + 2001ms | 每个 tick 向下取整，累计少 1 秒 | 毫秒余数跨采样保留，最终累计 4 秒 |
| Windows 活跃/空闲混合 | 三项可能各自取整，`session != active + idle` | 三个余数分别保留；会话秒数恒等于活跃 + 空闲 |
| Windows 跨午夜 | credit 整段落到新日 | 每日各自保留毫秒余数；午夜边界按最大余数确定性分配整数秒，旧日/新日不互相带走余数，总秒数不丢失 |
| Windows 最后活跃时间 | 空闲时仍写采样结束时刻 | 写作 `sample.wallNow - idleOverMs`（活跃区间末端） |
| Android journal 写失败 | 记录丢弃 | 放入内存 `pendingPersist` 队列；下次 observe/暂停/锁屏/停止前先重试，成功后才移除 |
| Android 同批多次写失败 | 后写记录覆盖式丢失 | 队列保持完成顺序，成功一个移除一个，不重复追加 |
| Android 设备标识不一致 | 自动确认并删除 | 不导入、不确认、不删除；结果增加 `deferred`，诊断页提示保留数量 |

## 4. 关键实现点

### Windows

- `lib/activity_tracking/activity_segment_service.dart`
  - `_OpenSegment.persisted`：开段是否已成功落库。
  - `_OpenSegment.pendingClose`：关闭失败后的结束时间、原因、最终秒数。
  - `_persistOpen()`：`insertIfAbsent` 幂等补插；插入成功后才通知 outbox。
  - `_finishClose()`：补插 → 关闭 → 删检查点 → 通知同步 → 清内存。
  - `_addDeviceUsage()`：按本地午夜拆分 session/active/idle 毫秒；空闲仍按时间边界拆分。
  - `_accumulateUsage()`：三个毫秒余数分别累计；会话秒数 = 活跃秒数 + 空闲秒数。
- `lib/database/dao/activity_dao.dart`
  - 新增 `insertIfAbsent()`（`INSERT OR IGNORE`），避免补写覆盖已存在的同 ID 行。

### Android

- `android/.../UsageSessionRecorder.kt`
  - 新增内存 `pendingPersist` + `pendingPersistIds`。
  - `flushCompleted()` 先 `retryPendingPersist()`，再写本次新记录。
  - 启动恢复写失败也进入同一队列；不新增第二套持久化文件。
- `lib/activity_tracking/android_usage_import_service.dart`
  - 非本机 `deviceLocalId` 只计入 `deferred`，不调用确认接口。
  - 诊断日志输出数量与去重后的原设备标识。
  - 同批合法记录继续导入、写 outbox、确认，不受异常记录阻塞。
- `lib/ui/widgets/overlay_pet_card.dart`
  - 诊断区显示：`发现 N 条设备标识不一致的暂存记录，已保留，未计入统计`。

## 5. 边界与取舍

- **跨午夜余数**：`daily_usage` 仍是整数秒，但每一天各自保存毫秒余数，旧日余数不会带入新日。
  午夜边界按“最大余数”确定性分配整数秒：例如旧日 800ms / 新日 1200ms，落盘为旧日 1 秒、新日 1 秒，总计 2 秒；不会出现旧日 0 秒、新日 2 秒。
- **Android 进程被杀**：`pendingPersist` 只在内存里，成功重试前进程被杀仍按现有检查点精度处理；本增量按要求不引入第二套持久化文件。
- **设备标识不一致记录**：保留在 journal 后仍按原生 FIFO 返回，若队头长期堆积大量此类记录，会占用单批读取名额；本轮不自动迁移归属，避免把真正的外部记录混入本机。
