### 1.3 右键菜单的事务外衣（用户怀疑的那层）

`lib/menu/context_menu_anchor.dart:65-76`

```dart
Future<T> runContextMenuRegionTransaction<T>({
  required Future<void> Function()? expandRegion,
  required Future<void> Function()? restoreRegion,   // ← 无 generation 参数
  required Future<T> Function() body,
}) async {
  await expandRegion?.call();
  try { return await body(); }
  finally { await restoreRegion?.call(); }            // ← 无条件执行
}
```

调用方 `ui/pet/pet_view_wrapper.dart:145-172` 的 `restoreRegion` 闭包**只检查 `mode`**：

```dart
if (windowsSurfaceSession.mode == WindowsSurfaceMode.petFixedCanvas) {
  await restoreRegion!.call();   // ← 只看“模式”，不看“现在 Region 归谁”
}
```

### 1.4 左键轮盘的入口

`DesktopShell`（`ui/desktop/desktop_shell.dart:584-592`）：

```dart
onPetTap: () {
  if (!_interactive) return;
  if (useFixed) { unawaited(fixedProbeKey.currentState?.toggle()); }

```

`FixedCanvasProbeState.toggle()`（`:251-256`）→ `_menuOpen ? close() : open()`。

## 2. 竞态的精确定位（可判定的失败序列）

### 2.1 两条独立所有权争同一块 HWND Region

- 右键链路：`expandRegionForOverlay()`（整块画布）→ `showMenu` → finally `restorePetOnlyRegionNow()`（pet-only）
- 左键链路：`open()`（pet+menu）→ `close()`（pet-only）

两者**互不知情**：右键链路不会去动 `_menuOpen`，左键链路也不会让右键事务失效。

### 2.2 失败时间线（场景 C：右键刚关闭瞬间左键）

```
t0  context_menu.open            owner=contextMenu   region=whole-canvas
t1  context_menu.close           用户点别处 / Esc，PopupRoute 开始退出
t2  wheel.open (左键 toggle→open)
    └ applyRegion(pet+menu)      region=pet+menu      ✅ 菜单可见可点
t3  restore.start (右键 finally)  ← 排在被 await 的 pop 动画之后
t4  restore.success              region=pet-only     ❌ 覆盖掉 pet+menu
    → 表现：轮盘“看起来打开了但没有 / 只有一小块 / 再点一次才恢复”
      右侧外围恢复点击，但轮盘被裁掉
```

`restore` 在 t3 执行时，`mode` **仍然是 `petFixedCanvas`**，所以 §1.3 的 `mode` 守卫**放行**——这正是「右键菜单的 try/finally 与左键轮盘分别直接写 Window Region，缺少统一所有权和 generation」的具体形态。

### 2.3 场景 D：右键仍开着时触发左键/双击

```
t0  context_menu.open            region=whole-canvas
t1  wheel.open                   region=pet+menu   （两者同时“以为”自己拥有 Region）
t2  context_menu.close → finally region=pet-only   ❌
t3  wheel.close                  region=pet-only   （重复写）
```

右键仍在开时左键，**两个 owner 同时认为 Region 是自己的**，没有仲裁者。

## 3. 修复方案：唯一 `RegionCoordinator`

### 3.1 新增文件（纯 Dart，可 `flutter_tester` 直测）

- `lib/menu/region_owner.dart` —— `RegionOwner` 枚举 + 优先级 + wireName
- `lib/menu/region_coordinator.dart` —— 唯一写入者 + generation + 事务校验 + 时间线日志
- `lib/menu/region_timeline.dart`（或复用 `wheel_geometry_ownership.dart` 的 `WheelGeometryJournal`）—— 事件记录

### 3.2 `RegionOwner` 与优先级

```dart
enum RegionOwner {
  pet,            // 仅桌宠矩形
  contextMenu,    // 整块画布（Overlay 需要）
  wheel,          // pet + menu
  panelTransition,// 无 Region（过渡期）
  panel,          // 无 Region（普通矩形窗口）
}
```

优先级（高 → 低，数值大者胜）：

```
panelTransition / panel  >  wheel  >  contextMenu  >  pet
```

### 3.3 唯一提交接口（禁止任何代码直接调用三条原生方法）

```dart
class RegionCoordinator {
  Future<RegionCommitResult> submit(RegionRequest request);  // 唯一入口
  Future<bool> clear(RegionClearRequest request);            // 唯一 clear 入口
}
```

**约束：`applyInteractionRegion` / `restorePetOnlyRegion` / `clearInteractionRegion` 只允许被 `RegionCoordinator` 调用。**
落地手段（三选一，建议 a+b 同时上）：
- a) 把 `WindowsSurfaceBridge` 的 `FixedCanvasRegionOps` 收窄为 `RegionNativeOps`，仅 `RegionCoordinator` 持有；
- b) `fixed_canvas_probe.dart` / `pet_view_wrapper.dart` / `desktop_shell.dart` 全部改为持有 `RegionCoordinator`；
- c) 加静态调用点断言测试（§7 测试 9），并在 CI 静态扫描 `lib/**` 里三条方法名的直接引用。

### 3.4 事务身份与三处校验点

每次 Region 操作必须携带并校验三元组：

```dart
class RegionTransaction {
  final int transactionId;      // 单调递增
  final int generation;         // 每次 owner / 目标 Region 改变 +1
  final RegionOwner expectedOwner;
}
```

**三个校验点（任一不符即记 `dropped_stale` 并放弃写入）：**
1. 真正调用原生**之前**；
2. `await` 原生返回**之后**；
3. `finally` 恢复**之前**。

`generation` 递增规则：**任一 owner 变更或目标 Region 变更都 +1**（不只是 owner 变更）。

## 4. 优先级与恢复语义（照需求逐条落地）

### 4.1 右键打开
`owner = contextMenu`，`region = whole-canvas`，`generation++`。

### 4.2 右键关闭 finally
```
if (tx.transactionId 已过期)                      → dropped_stale，什么都不做
else if (owner == contextMenu)                    → 恢复 pet（写 pet-only）
else if (owner == wheel)                          → 保持 pet+menu（不写）
else if (owner == panelTransition || panel)       → 不做任何恢复
else                                              → 不写
```
即：**右键关闭时不能无条件恢复 pet-only**，必须看当前 owner。

### 4.3 左键轮盘打开
1. 使 contextMenu 的 `transactionId` 失效（`generation++` 或 `invalidateOwner(contextMenu)`）；
2. `await contextMenuBridge.dismissAndWait()`（等待 popup 真正关闭）；
3. `owner = wheel`；
4. **只由 wheel 提交 pet+menu Region**。

### 4.4 轮盘关闭
仅当 `owner == wheel && generation 相同` 时，才恢复 pet-only；否则 `dropped_stale`。

### 4.5 面板切换
1. 使 contextMenu 与 wheel 的 transaction 全部失效；
2. `owner = panelTransition`；
3. **只有**模式事务可以 `clear` Region。

## 5. 禁止 Region 操作修改 Flutter 几何（硬约束）

`RegionCoordinator` 只允许调用三条 Region 原生方法（+ 两条只读诊断）。
**禁止**在其中出现：`setBounds` / `setSize` / `setPosition` / 改 `petAnchor` / 重建 `PetView` / 改菜单尺寸。

- 固定画布 HWND Rect 在左键开/关前后必须**逐像素一致**（已有 `FixedCanvasAssertions.evaluate`，容差 1px）。
- 落地手段：`RegionCoordinator` 的构造参数**不注入** `FixedCanvasWindowOps`；再加测试 9 断言「Region 事务期间 `windowOps.commitBounds` 调用次数 == 0」。

## 6. 左键入口状态机 `WheelInteractionState`

```dart
enum WheelInteractionState { closed, opening, open, closing }
```

| 规则 | 行为 |
|---|---|
| 只有 `closed` 才能 `beginOpen()` | 其余状态拒绝 |
| `opening` 时重复点击 | 忽略 |
| `open` 时点击业务按钮 | 不能重新 `open()` |
| `closing` 时点击 | 排队或忽略（本方案取**忽略**，避免队列残留） |
| 任何失败 | 回到 `closed`，并**通过 RegionCoordinator** 恢复正确 owner |
| 第二次点击 | **不得**作为布局修复手段 |

`beginOpen()` 必须在**同步段**内（首个 await 之前）把 `_state = opening` 置位——修掉 §1.4 的并发重入。

1. 冷启动直接左键。
2. 右键开关后左键。
3. 右键关闭瞬间快速左键。
