# 19 · 隐私与安全说明

> 本文件是 PetLife Phase 2 的隐私与安全权威说明。任何"能不能存/能不能传"的争议
> 以本文件为准；代码里凡是与本文件冲突的地方都算 bug。

## 1. 数据收集清单

### 1.1 采集（本地）

| 数据 | 是否采集 | 说明 |
|---|---|---|
| 前台应用标识 | ✅ | 规范化后的可执行文件名（`app_key`，如 `code`） |
| 应用分类 | ✅ | 8 类之一，可由用户修改 |
| 使用时间段 | ✅ | 起止时刻 + 有效活跃秒数 |
| 用户空闲时长 | ✅ | 只读**最后一次输入的"时刻"** |
| 锁屏 / 休眠状态 | ✅ | 只读布尔状态 |
| 屏幕会话 / 活跃 / 空闲秒数 | ✅ | 设备级每日汇总 |
| **窗口标题** | ❌ | 结构里没有这个字段 |
| **文档名称 / 网页标题 / URL** | ❌ | 同上 |
| **本地完整文件路径** | ❌ | `app_key` 必须先在客户端规范化；服务端还会拒绝含路径分隔符的值 |
| **键盘输入内容** | ❌ | 不装任何键盘钩子 |
| **鼠标内容 / 轨迹** | ❌ | 只用 `GetLastInputInfo` 读时刻 |
| **剪贴板** | ❌ | 无任何剪贴板 API 调用 |
| **屏幕截图** | ❌ | 无任何屏幕抓取 API 调用 |
| **硬件指纹**（序列号 / MAC） | ❌ | `device_local_id` 是本地随机 UUID，可随时撤销 |

### 1.2 上传（服务端）

只上传：应用使用时间段、每日用量快照、应用库的 4 个安全字段
（`app_key` / 可公开的显示名 / 分类 / 是否人工分类）、设备自报元数据。

**不上传**：素材文件、日志文件、本地数据库、任何内容类数据。

## 2. 服务端存储的数据

| 表 | 列（数据部分） | 隐私说明 |
|---|---|---|
| `users` | email、display_name、password_hash、status | 密码只有 Argon2id 哈希 |
| `devices` | device_local_id、device_name、platform、architecture、os_version、app_version、model_name | 全部是客户端自报，无硬件指纹 |
| `refresh_tokens` | `sha256(token)`、签发/过期/撤销时间 | **不存明文令牌** |
| `activity_segments` | app_key、category、started_at、ended_at、active_seconds、end_reason | **无窗口标题、无 URL、无路径** |
| `daily_usage` | local_day、时区偏移、会话/活跃/空闲秒数 | 设备级汇总 |
| `user_applications` | app_key、display_name、category、user_overridden | **只有这 4 个数据字段** |
| `sync_log` | 实体类型、记录键、操作、时间 | 游标用 |

`test_migrations.py::test_migrated_schema_contains_no_privacy_columns` 会扫描
所有表的列名，一旦出现 `title` / `url` / `file_path` / `screenshot` / `clipboard`
之类的片段就**直接失败**。这是防回归的机器断言，不靠人记得。

## 3. 传输安全

### 3.1 开发环境

允许直接用 HTTP 访问 `localhost` / `127.0.0.1`（不经过网络）。

### 3.2 生产环境（必须 HTTPS）

Bearer 令牌与 Refresh Token 都在请求里出现，**HTTP 明文传输等于把账户交出去**。
生产必须：

1. 反向代理（Caddy / Nginx）终止 TLS；
2. compose 的 `API_BIND_ADDRESS` 保持 `127.0.0.1`，只让反代能访问 API；
3. 绝不把 `8000` 端口直接暴露到公网。

### 3.3 代理（Clash / HTTP CONNECT）

客户端支持经 HTTP 代理（Clash 的 System Proxy 或手动 HTTP/Mixed Port）访问服务端。
代理只改变**传输路径**，不改变协议与数据内容。

**绝不通过代理绕过 TLS 校验**：

- 代码里**没有**任何 `badCertificateCallback` 赋值（`api_client` 有一条专门的测试断言它始终为 `null`）；
- `SecureSocket` 也没有传 `onBadCertificate`；
- 证书错误只会被报告（`tlsHandshakeFailed`），不会被"忽略后继续"。

代理凭据（用户名/密码）的处理见 §7.5。

## 4. 认证安全

| 措施 | 实现 |
|---|---|
| 密码哈希 | **Argon2id**（`time_cost=3`, `memory_cost=64MiB`, `parallelism=4`） |
| 密码长度 | 8~128 字符上限（防超长输入放大哈希开销） |
| Access Token | JWT HS256，15 分钟，含 `iss` / `exp` / `typ` 校验 |
| Refresh Token | 不透明 48 字节随机串，服务端**只存 SHA-256**，30 天 |
| Refresh 轮换 | 每次刷新换新令牌，旧令牌立即失效并记录轮换链 |
| 泄露检测 | 已轮换的旧令牌再次出现 → 吊销该用户**全部**会话 |
| 吊销即时性 | 注销 / 改密 / 删号 / 撤销设备都会立刻更新数据库，无需等过期 |
| 防令牌类型混用 | `typ` 声明区分 access / refresh（有测试） |
| 防邮箱枚举 | 登录错误不区分"邮箱不存在"与"密码错误" |
| 防弱密钥 | `PETLIFE_JWT_SECRET` 缺失或为占位值 → **启动直接失败** |
| 防默认弱口令 | compose 未设置 `POSTGRES_PASSWORD` → **直接报错退出** |

## 5. 日志安全

需求：**日志不得输出 Access Token、Refresh Token、Authorization 请求头或密码。**

实现分两层（`server/app/core/logging.py`）：

1. **访问日志只记元数据**：`request_id` / method / path / status / 耗时，
   **从不记录请求体、请求头、query**；
2. **`RedactingFilter` 兜底**：装在 handler 上（不是 logger 上——Python 的
   logger 过滤器对子 logger 的记录不生效），对**任何**到达 handler 的记录做正则脱敏：

   | 模式 | 例 |
   |---|---|
   | `Bearer/Basic <值>` | `Authorization: Bearer eyJ...` → `<redacted>` |
   | 三段式 JWT | 裸 `eyJ...eyJ...sig` → `<redacted>` |
   | `key=value` / `"key": "value"` | `password=hunter2`、`"refresh_token":"..."` → `<redacted>` |

验证：

- `tests/test_logging_redaction.py`：15 项，包含「真实登录请求产生的日志里
  不含密码与令牌」；
- `tools/e2e_smoke.py` 第 11 步：读真实 uvicorn 输出，断言不含密码 /
  Access Token / Refresh Token。

## 6. 数据隔离

用户 A 无法读取或改写用户 B 的任何数据。实现**不依赖"记得加 where 条件"**：

- `activity_segments` 主键 = `(user_id, id)`
- `daily_usage` 主键 = `(user_id, device_id, local_day)`
- `user_applications` 主键 = `(user_id, app_key)`
- 所有 pull / stats 查询都以 `user_id` 为第一条件

测试文件 `test_isolation.py`（6 项）覆盖：

- A 的数据不出现在 B 的 pull 结果里；
- B 重放 A 的记录 UUID → 只写入 B 名下，A 的数据一字不改；
- 统计按用户隔离；
- B 不能读/改/撤销 A 的设备（统一返回 `device_not_found`，**不泄露设备是否存在**）；
- 应用库按用户隔离；
- 同一用户的两台设备同日数据各占一行。

## 7. 令牌的本地保存（客户端实现）

### 7.1 后端优先级

Windows 客户端**按顺序探测**，用探针条目（写入 → 读回 → 比对 → 删除）确认可用性，
三步都成功才采用；后端名会显示在账户页与诊断页，**不做静默降级**。

| 顺序 | 后端 | 实现 | 说明 |
|---|---|---|---|
| 1 | **Windows Credential Manager** | `CredWriteW` / `CredReadW` / `CredDeleteW`（Dart FFI，`advapi32`） | 首选。凭据类型 `CRED_TYPE_GENERIC`，条目名 `PetLife:account`；超过 `CRED_MAX_CREDENTIAL_BLOB_SIZE`（2560 字节）时自动退化 |
| 2 | **DPAPI 文件后端** | `CryptProtectData` / `CryptUnprotectData`（`crypt32`） | ⚠️ **用户范围加密**（不加 `CRYPTPROTECT_LOCAL_MACHINE`），密文只能被**同一个 Windows 用户**解开；密文放 `<AppData>/PetLife/credentials/<条目名>.bin`，**不是 SQLite** |
| 3 | `InMemoryCredentialStore` | 纯 Dart | 仅用于测试与"两个后端都不可用"的诊断场景，重启即丢令牌（用户需重新登录） |

Access Token 与 Refresh Token **一起**存在凭据条目里（一个 JSON），
因此不存在"一半在凭据管理器、一半在别处"的不一致状态。

### 7.2 明确不落盘的东西

- SQLite 中**绝不明文保存密码**（客户端根本不保存密码，登录后即丢弃）；
- SQLite 中**不保存任何令牌**：`account_session_state` 只有
  `credential_reference`（条目名）+ `access_token_expires_at`（用于判断是否该提前刷新）；
- 令牌**不进日志**、不进异常消息、不进 HTTP 调试输出。

`test/sync_security_test.dart` 用两条机器断言兜住：

1. `AccountSession 落库后，直接扫描整个 `.db` 文件字节，搜不到令牌字符串`；
2. `PRAGMA table_info(account_session_state)` 里不存在 `token` / `password` 类列名。

### 7.3 清理时机

| 触发 | 客户端行为 |
|---|---|
| 用户点「退出登录」 | 删除凭据条目 + 清空 `account_session_state`；**本地使用记录与素材保留**（采集继续） |
| 修改密码 | 服务端吊销全部会话 → 客户端刷新失败 → 清令牌，进入 `needsReauthentication` |
| 账户被删除 | 同上（服务端返回 401） |
| 设备被撤销 | 服务端返回 401/403 → 清令牌，`needsReauthentication`，**本地采集继续** |
| Refresh Token 失效/被轮换后重放 | 服务端吊销全部会话 → 同"修改密码" |

### 7.4 客户端日志脱敏（实现细节）

服务端有 `RedactingFilter` 兜底，客户端有对应的一层：`lib/core/logger.dart` 的 `AppLog.redact()`。
**它作用在 `AppLog.format()` 上**，因此生效范围覆盖文件日志、内存环形缓冲、诊断页与导出文本 ——
四条出口共用同一个 `format()`。

规则按**顺序**应用（顺序有讲究：先处理"值里含空格"的，再处理裸值）：

| 模式 | 例 |
|---|---|
| `Bearer <值>` / `Basic <值>` | `Authorization: Bearer eyJ...` → `Bearer <redacted>` |
| 三段式 JWT | 裸 `eyJ...eyJ...sig` → `<redacted>` |
| `key=value` / `"key":"value"` | `access_token=...`、`"refresh_token":"..."`、`password=hunter2`、`client_secret`、`api_key`、`credential` 等 → `<redacted>` |

`test/sync_security_test.dart` 覆盖 9 类敏感串，并单独断言
「经过 `AppLog.format()` 之后一定不含原文」（即"脱敏函数存在但忘了调用"这类回归会被抓到 ——
**这正是实现过程中真实发现并修掉的 bug**：`format()` 原先从未调用 `redact()`）。

### 7.5 代理密码（Clash / HTTP 代理）

代理支持引入的第二份凭据，规则与令牌**完全一致**：

| 项 | 做法 |
|---|---|
| 存储位置 | `CredentialStore`，条目名 `PetLife:proxy`（与账户令牌同级，同一后端优先级） |
| SQLite 里存什么 | 只存 `sync.proxyPasswordReference = 'PetLife:proxy'` 这个**引用名**；密码本体不落库 |
| `ProxySettings` 有没有密码字段 | **没有**（这是刻意的：模型层面就无法把密码写进配置表） |
| 日志 | 统一脱敏；`Proxy-Authorization` 与 `proxy_password` 都进了 `AppLog.redact()` 的规则（有测试） |
| 请求头 | 只在 CONNECT / 代理认证时写入 socket 或交给 `addProxyCredentials`，**没有一处进日志** |
| 清除路径 | 界面上的「清除已保存的密码」；退出登录**不会**清除代理密码（它不属于账户） |

引导用户时的提示也写清了这点：界面上的密码框注明"密码保存在系统凭据存储中，
不写入本地数据库"。

**PAC/WPAD 明确不支持**：检测到 `AutoConfigURL` 或自动检测（WPAD）时会**明确提示**
"PetLife 暂不支持 PAC，已退回直连"，绝不静默假装成直连（那样用户会以为代理生效了，
实际流量却走了别的路）。

## 8. 数据删除

| 操作 | 效果 |
|---|---|
| 客户端「退出登录」 | **只清理认证信息**；本地使用记录与桌宠素材**保留** |
| 服务端「注销当前会话」 | 该 Refresh Token 失效 |
| 服务端「注销全部会话」 | 该账户全部 Refresh Token 失效 |
| 服务端「撤销设备」 | 该设备令牌失效 + 释放 `device_local_id`；数据保留（仍可查询） |
| 服务端「删除账户」 | 吊销全部令牌；**物理删除设备及其活动段 / 每日用量**；账户置为 `deleted`；邮箱释放；密码哈希置为随机值 |
| 用户手动删除本地数据 | 由客户端提供（Phase 2 客户端部分） |

## 9. 已知限制

1. **服务端没有速率限制**：登录/注册接口可被暴力尝试。
   生产必须在前置反代上配置限流（如 Caddy `rate_limit` 或 Nginx `limit_req`），
   或后续阶段在应用层加。本阶段**未实现**，已在此明确记录而不是假装有。
2. **没有邮箱验证与找回密码**：当前注册即可用；忘记密码需要重新注册。
3. **Access Token 无法按单个会话提前吊销**：它是自包含 JWT，
   撤销设备/改密后会通过数据库校验拦截（`status` / `device.revoked_at`），
   但纯签名校验层面无法逐个撤销；最长 15 分钟窗口内靠上述数据库校验兜住。
4. **没有审计日志**：登录历史、设备撤销历史目前只进普通日志文件。
5. **SQLite 作为服务端存储仅用于开发**：并发写入能力有限，生产必须用 PostgreSQL。
6. **HTTPS 需要你自行配置**：本仓库提供 compose 与反代示例，但不会自动部署。
7. **客户端"删除本地使用记录"的 UI 尚未提供**：Phase 2 客户端实现了「退出登录」（只清认证信息），
   但没有一键清空本地使用记录 / 素材的界面。需要清除时可手工删除
   `<AppData>/PetLife/petlife.db*`，或在后续阶段补 UI。
8. **HttpOnly/secure 之类的浏览器侧保护不适用**：这是桌面客户端，
   令牌保护完全依赖 §7 的凭据后端；若两个后端都不可用会退化到内存（重启需重新登录），
   此时账户页会显示后端名，用户可据此判断令牌是否真的被持久化保护。
9. **服务端地址可被用户改成 HTTP 明文地址**：客户端允许配置 `http://`（开发需要），
   **不强制 HTTPS**。生产部署时请把服务端地址配置为 HTTPS 地址；
   客户端本身不做"非 localhost 必须 HTTPS"的强校验。
