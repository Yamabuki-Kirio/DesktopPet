# 12 · 使用统计口径

> 适用范围：**PetLife 阶段 1**。本文件是「界面上每个数字到底怎么算」的唯一权威解释。

## 1. 四个必须区分的指标

需求「九、屏幕使用时长」明确要求区分这些指标，界面**不能**笼统地都叫「屏幕时间」。
统计页的「概览」卡片把它们并排展示，并标注了定义。

| 指标 | 界面名 | 定义 | 数据来源 |
|---|---|---|---|
| 屏幕会话时间 | 屏幕会话时间 | 设备**解锁且未休眠**的总时间 | `daily_usage.session_seconds` |
| 活跃使用时间 | 活跃使用时间 | 屏幕会话中，用户空闲**未超过阈值**的时间 | `daily_usage.active_seconds` |
| 空闲时间 | 空闲时间 | 解锁但用户空闲**超过阈值**的时间 | `daily_usage.idle_seconds` |
| 应用使用时间 | 应用使用时间 | 活跃时间中**归属到有效前台应用**的部分 | `activity_segments.active_seconds` |

**恒等关系**：

```
屏幕会话时间 = 活跃使用时间 + 空闲时间
应用使用时间 ≤ 活跃使用时间
```

第二行是「≤」而不是「=」，因为活跃时间里可能存在**没有有效前台应用**的时刻
（例如刚解锁尚未切换窗口、系统弹窗、前台进程信息读取失败），
这些时间算「设备活跃」，但没有应用可归属。

锁屏与休眠的时间**既不算会话也不算空闲**（设备不可用），因此三者不会把一整天加满。

## 2. 各指标的判定条件

只有同时满足以下全部条件，时间才计入**活跃使用**：

1. Windows 未锁屏；
2. 系统未休眠；
3. 用户空闲 < 阈值（默认 5 分钟，可设 1 / 3 / 5 / 10 / 15 分钟）；
4. 用户没有暂停记录。

在此之上，还要满足以下全部条件，时间才计入**应用使用**：

5. 存在有效前台应用（能取到进程名或可执行路径）；
6. 该应用不在排除名单（含 PetLife 自身）。

## 3. 空闲边界

「空闲超过阈值」不是从**检测时刻**开始算，而是从**真正越过阈值的那一刻**开始算。

检测到 `idle ≥ 阈值` 时：

```
结束时刻 = 本次采样时刻 − (idle − 阈值)
```

因此一次 5 分 3 秒的空闲，只会让活跃时间停止增长 3 秒前的那一刻，不会把
「达到阈值之后才被采样到」的那段延迟误算进去。

单次采样的计入量还额外受 `maxCreditPerTickMs = 6 秒`（3 × 采样间隔）限制，
避免一次卡顿把几十秒都算成用户活跃。

## 4. 活动段的裁剪与跨日归属

统计窗口是**半开区间** `[from, to)`。与窗口有交集的活动段会被裁剪：

```
裁剪后的活跃秒数 = 该段活跃秒数 × (落在窗口内的墙钟毫秒 / 该段墙钟总毫秒)
```

- 完全落在窗口内的段 → 原值（比例为 1，不引入误差）；
- 跨零点的段 → 按比例拆到两天，两天之和等于原值（**不增不减**）。

跨日还有一层保障：`daily_usage` 按「本地日期键」分行存储，
`ActivitySegmentService._ensureDay()` 在日期变化时先把前一天的计数落盘，再切换到新的一行。

## 5. 时区

### 5.1 应用统计

`UsageWindow` **显式携带时区偏移**，而不是依赖运行时的 `DateTime.now()` 本地时区：

```dart
UsageWindow.dayContaining(nowUtc, tzOffset)
UsageWindow.lastDays(nowUtc, tzOffset, days: 7)
UsageWindow.weekContaining(nowUtc, tzOffset)   // 周一 00:00 起
```

好处有两个：跨日/跨窗口归属有确定公式；单元测试可以直接构造
`+08:00` 与 `-05:00` 两种情形做断言，而不依赖测试机的时区设置。

### 5.2 设备级统计（`daily_usage`）

`day_key` 是**写入当时的本地日期**（`YYYY-MM-DD`）。历史记录不会因为用户之后修改
系统时区而被重写——这符合「历史数据应当稳定」的直觉。

副作用：用户改了时区之后，按新的本地日期键可能查不到当天的行。
统计服务对此有兜底：若按日期键一条都没命中，则改用「行最后更新时间落在窗口内」的行补上，
避免概览突然变成 0。

## 6. 应用排行与分类统计

- **应用排行**：按应用聚合裁剪后的活跃秒数，倒序；同时给出「使用段次数」
  （`activity_segments` 的行数）与「占应用使用时间的比例」。
- **分类统计**：先按 `app_key` 找到应用库里的分类，再聚合。
  应用库里没有记录的应用归入 `other`（不会报错、不会丢数据）。
- 比例的分母统一是**应用使用时间**，因此排行比例与分类比例各自合计为 100%。

## 7. 最长连续使用时间

把窗口内裁剪后的活动段按时间排序，相邻间隔 ≤ **60 秒**（`continuousGapToleranceMs`）
视为「同一段连续使用」，累加活跃秒数；取所有连续段中的最大值。

容差的存在是必要的：应用切换本身会产生相邻的小段，若严格要求首尾相接，
一次正常的工作过程会被拆成几十段，最长连续使用时间将失去意义。

## 8. 首次 / 最后活跃时间

取当天（或窗口内各天）设备级活跃区间的**最早起点**与**最晚终点**，
来自 `daily_usage.first_active_at` / `last_active_at`。
界面只显示到分钟（`HH:mm`）。

## 9. 设备隔离

所有查询都按 **owner + 设备** 过滤（`AppConstants.localDeviceId`），
**绝不跨设备求和**：

- `activity_segments` 与 `daily_usage` 都带 `device_local_id`；
- `UsageAnalyticsService.summarize()` 始终带上设备条件；
- 因此同一账号在多台机器上产生的数据不会互相污染。

## 10. 已知的口径限制

| 限制 | 说明 |
|---|---|
| 进行中的段有 ≤30 秒的落库延迟 | 段只在检查点（30 秒）或结束时回写。统计页查询前会调 `flushNow()`，因此界面数字是最新的；直接读数据库的第三方工具可能看到稍旧的值 |
| 跨日裁剪按墙钟比例分摊 | 若某段内部既有活跃也有空闲，按比例分摊会引入少量误差（量级为分钟）；完全落在窗口内的段无误差 |
| 多显示器 / 多桌面 | 只统计**当前前台窗口**所属进程，不区分窗口在哪个显示器 |
| 应用切换的 1.5 秒确认窗口 | 短于 1.5 秒的切换其时间归属上一个应用，这是抑制碎片段的代价 |
| 时区变更 | 历史 `daily_usage.day_key` 不重写（见 §5.2） |

## 11. 服务端口径一致性（Phase 2）

服务端统计（`GET /api/v1/stats/*`）**必须与客户端使用同一套口径**，
否则「客户端看到的今日数据」和「网页看到的」会对不上。为此：

| 口径要素 | 客户端 | 服务端 | 是否一致 |
|---|---|---|---|
| 四个指标的来源 | `daily_usage` + `activity_segments` | 同名两表 | ✅ |
| 会话 = 活跃 + 空闲 | `daily_usage` 累加 | 同 | ✅ |
| 应用使用 ≤ 活跃使用 | 是 | 是 | ✅ |
| 跨界段按墙钟比例折算 | 按重叠毫秒 / 段总墙钟 | 同（`_clip()`） | ✅ |
| 跨日拆分不增不减 | 两天之和 = 原值 | 同 | ✅ |
| 「今天」的边界 | 客户端本地时区 | **由客户端传 `tz_offset_minutes`** | ✅ |
| 多设备求和不去重 | 客户端只统计本设备 | 服务端按设备分行 + 合计并带 `overlap_warning` | ✅（口径显式） |
| 瞬时口径（进行中的段最多落后 30 秒） | 查询前 `flushNow()` | 客户端已落库，服务端看到的就是落库值 | ✅ |

### 11.1 服务端与客户端的两处刻意差异

1. **服务端多了 `yesterday` 区间**。客户端有「昨天」，服务端也提供，
   便于跨日拆分做对照验证；`7d` / `30d` 含义两边一致（含今天的 N 天）。
2. **服务端可以按设备过滤（`device_ids`）**，客户端当前只统计本设备。
   这是为了支持"多设备数据查询"这一需求；两端在**同一设备**上的数字应当完全一致。

### 11.2 服务端多设备口径的措辞要求

需求明确要求「多设备总时长可以求和，但界面必须明确这是'设备使用时长合计'，
不同设备同时使用可能发生时间重叠」以及「不得偷偷将重叠设备时段去重」。
服务端响应里固定带上：

```json
{
  "total_active_seconds": 5400,
  "overlap_warning": "这是各设备使用时长的合计；同一账号在多台设备上并行使用时时间会重叠，该合计未做去重。"
}
```

客户端展示多设备数据时**必须**原样呈现这条提示，不得只显示数字。
有测试断言该字段存在且包含「重叠」字样。
