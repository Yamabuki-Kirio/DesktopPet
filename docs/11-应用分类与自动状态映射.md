# 11 · 应用分类与自动状态映射

> 适用范围：**PetLife 阶段 1**。

## 1. app_key：稳定且不含隐私内容的应用标识

`app_key` = **规范化后的可执行文件名**，规则（`lib/activity_tracking/app_keys.dart`）：

```
C:\Program Files\Microsoft VS Code\Code.exe  →  code
C:\Apps\Chrome.EXE                            →  chrome
Telegram.exe                                  →  telegram
C:\Apps\                                      →  null（宁可不记录，也不写虚假应用名）
```

处理步骤：取路径最后一段 → 统一小写 → 去掉 `.exe` → 去首尾空白 → 空串返回 `null`。

**第一版不使用窗口标题作为应用主键**，因此：

- 同一应用升级、换安装目录后 `app_key` 不变；
- 不同文档/网页不会产生「新应用」；
- 记录里天然不存在标题类隐私数据。

展示名（`display_name`）默认取可执行文件名并保留原始大小写（`Code.exe → Code`），用户可随时改写。

## 2. 分类体系

8 个分类，`wireName` 为持久化与统计口径的稳定标识：

| wireName | 中文 | 典型应用 |
|---|---|---|
| `development` | 开发 | VS Code、Visual Studio、IDEA、PyCharm、Rider、终端、Notepad++ |
| `productivity` | 生产力 | Word、Excel、PowerPoint、Outlook、WPS、Notion、Obsidian、Photoshop |
| `gaming` | 游戏 | Steam、Epic、战网、Valorant、Cyberpunk 2077 等 |
| `social` | 社交 | Telegram、Discord、微信、QQ、钉钉、飞书、Zoom、Teams |
| `entertainment` | 娱乐 | PotPlayer、VLC、Spotify、网易云音乐、哔哩哔哩、照片 |
| `browser` | 浏览器 | Chrome、Edge、Firefox、Brave、Opera、Vivaldi |
| `system` | 系统 | 资源管理器、任务管理器、注册表、设置、Shell 宿主 |
| `other` | 其他 | 未命中任何规则的应用 |

完整规则表见 `kBuiltInCategoryRules`（`application_classifier.dart`），约 130 条。

## 3. 判定优先级

严格按需求的顺序，**人工设置永远最高**：

```
1. 用户手工分类（applications.user_overridden = 1）
2. 内置进程名规则（kBuiltInCategoryRules）
3. 安装路径特征（kGamePathMarkers，游戏为主）
4. other（无法确定时不猜测）
```

每条结果都带 `ClassificationSource`（用户设定 / 内置规则 / 路径特征 / 默认归类），
可在统计页与日志中看到依据，便于排查误分类。

### 3.1 游戏识别

按需求「游戏识别优先采用：用户手动分类 → 已知游戏进程规则 → Steam 安装信息或进程路径特征 → other」：

已知进程规则：`steam` / `epicgameslauncher` / `battle.net` / `valorant` / `cyberpunk2077` 等约 20 条。

路径特征（大小写不敏感的子串匹配）：

```
\steamapps\common\  \steamapps\  \epic games\  \gog galaxy\games\
\gog games\  \riot games\  \battle.net\  \xboxgames\  \games\  \game\
\ubisoft game launcher\games\
```

**绝不使用窗口标题猜测游戏**——标题里出现 "Game" 之类的字样不会被当成游戏。

### 3.2 人工分类的持久化语义

用户改分类时同时写入 `category` 与 `user_overridden = 1`。
此后内置规则**永远不会**覆盖它，即使应用被重装、路径变化也一样。

## 4. 排除规则

| 来源 | 内容 |
|---|---|
| 内置排除 | `petlife`（PetLife 自身，需求明确要求） |
| 用户排除 | `applications.excluded = 1` |
| 无有效进程信息 | 采样返回 null → `process_unavailable`，不记录 |

被排除的应用**仍然登记进应用库**，否则用户无法在统计页里把它恢复记录。

用户可执行的操作：排除指定应用 / 恢复记录 / 暂停全部记录 / 恢复全部记录 / 查看当前是否正在记录。
**暂停时立即结束当前活动段**，不等下一个采样周期。

## 5. 状态映射表

`ActivityStateMapper` 是一个纯函数，优先级从高到低：

| 优先级 | 条件 | 桌宠状态 | 触发源 | 说明 |
|---|---|---|---|---|
| 1 | 采集器或数据库严重错误（连续 ≥3 次落盘失败） | `error` | `error` | 唯一 `isUrgent = true` 的自动判定 |
| 2 | 今日活跃 ≥ 用户设定阈值（默认关闭） | `concerned` | `foregroundApp` | 阈值 0 = 关闭 |
| 3 | 连续活跃 ≥ 90 分钟且提醒开启 | `tired` | `foregroundApp` | 与 `away` 互斥（见下） |
| 4 | 空闲 ≥ 阈值（默认 5 分钟） | `away` | `idle` | |
| 5 | 前台分类 = 开发 / 生产力 | `focused` | `foregroundApp` | |
| 5 | 前台分类 = 游戏 | `gaming` | `foregroundApp` | |
| 5 | 前台分类 = 社交 | `social` | `foregroundApp` | |
| 5 | 前台分类 = 娱乐 | `entertained` | `foregroundApp` | |
| 5 | 前台分类 = 浏览器 / 系统 / 其他 | `default` | `foregroundApp` | |
| — | 采集不可用 | **返回 null，不干预** | — | 避免把桌宠钉死在某个状态 |

### 5.1 为什么浏览器映射为 default

仅凭「前台是浏览器进程」无法区分用户在工作（在线文档、代码托管）还是在娱乐（视频、游戏网页）。
强行映射成 `focused` 或 `entertained` 都会给出**错误信息**，因此保持 `default`。
这是需求「十」的明确要求。

### 5.2 tired 与 away 的互斥

连续活跃计数在「空闲超过阈值 / 锁屏 / 休眠 / 暂停 / 正常退出」时归零，
因此用户离开后 `tired` 不可能同时成立，两条规则不会互相打架。

### 5.3 manual 的绝对优先

`manual` **不参与**上述判定：

- 映射器在任何情况下都不会返回 `manual`（有测试断言）；
- 阶段 0 的状态引擎里 `SystemState.manual` 的 `minHoldMs = -1`，且
  `StateDebouncer` 会在 `manual` 状态下拒绝一切 `force = false` 的请求，
  而自动状态一律以 `force = false` 发出（见 §6）；
- 因此**手动锁定表情永远不会被自动检测覆盖**；
- 解除锁定后 `releaseManual()` 回到 `default`，自动切换随即恢复。

## 6. 请求参数：自动 vs 手动

| 场景 | force | immediate | 结果 |
|---|---|---|---|
| 自动状态（本文件描述的全部判定） | `false` | `false` | 尊重优先级与最短展示时长，并**等待当前动画播完一轮**再淡入（平滑切换） |
| 状态调试器手动触发 | `true` | `true` | 立即生效，用于人工验证 11 个状态 |
| 用户锁定表情（`manual`） | `true` | `true` | 立即生效 |

自动状态一律 `immediate = false`，这是需求「十」的硬要求：不打断正在播放的动画。

## 7. 状态请求的节流

`ActivityTracker` 只在「映射出的状态 ≠ 引擎当前状态」时才发起请求。两个好处：

1. 不会每 2 秒产生一条「状态未发生变化」的拒绝日志；
2. 不会重复请求从而干扰引擎自己的「推迟后重试」计时
   （前台应用需稳定 10 秒这条规则正是靠引擎的推迟重试实现的）。

因此真实的时序是：**切换到开发工具 → 引擎推迟 10 秒 → 自动重试并生效**，
而统计页与托盘里的「当前应用」在 2 秒内就会更新（两者是不同指标，见 `12-使用统计口径.md`）。
