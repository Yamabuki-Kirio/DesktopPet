# 32 - 对话框生命周期与控制器归属

> 记录 2026-09-29 真机上两个必现崩溃（素材导入、设备改名）的根因与统一修复。
> 相关验收状态见 [29-Phase4测试与验收报告.md](29-Phase4测试与验收报告.md) §4.0。
> 上一轮的真机缺陷（数据库 PRAGMA）见 [31-Android数据库启动失败与PRAGMA兼容性.md](31-Android数据库启动失败与PRAGMA兼容性.md)。

## 1. 现象（真机，两处，同一句断言）

| # | 操作 | 结果 |
|---|---|---|
| 1 | 素材库 → 导入图片 → **情绪名称留空** → 点导入 | 断言崩溃 |
| 2 | 账户与同步 → 修改本机 → 改设备名称 → 保存 | 断言崩溃 |

两处报的是同一句：

```text
'package:flutter/src/widgets/framework.dart'
Failed assertion: line 6281 pos 12: '_dependents.isEmpty': is not true.
```

留空本身是**合法功能**（"留空则用文件名解析"），不是错误输入 —— 所以不能靠
"禁止留空"绕开。

## 2. 根因：控制器的所有者错了

改造前两处都是同一个形状（以设备弹窗为例）：

```dart
// ❌ 改造前：控制器属于**调用方**，却在弹窗路由还没走完退场动画时被销毁
final TextEditingController name = TextEditingController(text: ...);
final bool? saved = await showDialog<bool>(context: context, builder: (ctx) => AlertDialog(
  content: TextField(controller: name, ...),
));
name.dispose();          // ← 问题在这里
```

关键在于 `showDialog` 的 Future 什么时候完成：

* `Navigator.pop` 会**立刻**完成那个 Future（`Route.didComplete`）；
* 但弹窗的 Element 要等**退场动画结束**才 unmount，`State.dispose()` 也在那时才跑。

于是"调用方认为弹窗已经结束"与"控件仍然挂在树上"之间存在一个时间窗：

```
tap 导入/保存
   │
   ├─ Navigator.pop ──► showDialog 的 Future 完成 ──► 调用方恢复执行
   │                                                   name.dispose()  ← 控制器已销毁
   │
   └─ 退场动画（~150ms）──► 弹窗 Element unmount ──► TextField 才发现控制器没了
                                                      → 依赖关系被打乱
                                                      → InheritedElement.debugDeactivated()
                                                        assert(_dependents.isEmpty) 失败
```

`framework.dart:6281` 正是：

```dart
@override
void debugDeactivated() {
  assert(_dependents.isEmpty);   // ← 这一句
  super.debugDeactivated();
}
```

> **为什么不能用 `addPostFrameCallback` / `await Future.delayed(...)` 绕过**：
> 那只是把"何时销毁"赌在一个猜出来的延时上，弹窗动画时长、系统动画缩放、
> 低端机掉帧都会让这个赌注失败；而且每多一个弹窗就要重新赌一次。
> 正确的做法是**让所有者与生命周期对齐**。

## 3. 统一修复：控制器归弹窗自己的 State

新增三个独立弹窗组件（`lib/ui/dialogs/`）：

| 文件 | 组件 | 结果对象 | 取代 |
|---|---|---|---|
| `asset_import_form_dialog.dart` | `AssetImportFormDialog` | `AssetImportForm` | `asset_library_page._askFileImportForm()` |
| `device_edit_dialog.dart` | `DeviceEditDialog` | `DeviceEditResult` | `account_sync_page._editCurrentDevice()` |
| `text_input_dialog.dart` | `TextInputDialog` | `String?` | `usage_stats_page._promptText()`（审计发现的同类写法） |

三者都遵守同一条规则：

```dart
class _DeviceEditDialogState extends State<DeviceEditDialog> {
  late final TextEditingController _name;

  @override
  void initState() { super.initState(); _name = TextEditingController(text: ...); }

  @override
  void dispose() { _name.dispose(); super.dispose(); }   // ← 与路由同生共死
}
```

* **谁创建谁销毁**：控制器由弹窗 State 创建、由同一个 State 销毁，
  销毁发生在路由 unmount 时 —— 不再存在"控件还依赖、控制器已销毁"的窗口；
* **调用方只拿结果**：`await AssetImportFormDialog.show(...)` 拿到的是**不可变**的
  `AssetImportForm` / `DeviceEditResult`，调用方代码里**不再出现任何控制器**；
* 表单校验也在弹窗内部完成（`Form` + `GlobalKey<FormState>` 都属于弹窗 State）。

调用方因此简化成：

```dart
final DeviceEditResult? result = await DeviceEditDialog.show(context, ...);
if (result == null) return;      // 取消
```

### 3.1 素材导入的语义（保持不变）

| 字段 | 留空时的行为 |
|---|---|
| 作品包名称 | 回落到调用方给的默认作品包名称（`fallbackPackName`） |
| 角色名称 | 返回 `null` → 由导入层按文件名解析 |
| 情绪名称 | 返回 `null` → 由导入层按文件名解析 |

留空是合法输入；**取消返回 `null`**，调用方据此不执行导入。

### 3.2 设备编辑的校验（新增，关闭前完成）

| 字段 | 规则 |
|---|---|
| 设备名称 | 不能为空；长度 ≤ 128 |
| 型号备注 | 允许为空；长度 ≤ 128 |

* 长度按 **Unicode 码点**计数（`String.runes.length`），与服务端 Python 的 `len()`
  口径一致（`String.length` 数 UTF-16 码元，emoji 会被多算）；
* 与服务端 `DeviceUpdateRequest`（`device_name: min_length=1, max_length=128`、
  `model_name: max_length=128`）对齐，避免"客户端放行、服务端 422"；
* 校验失败**不 pop**：弹窗保持打开，错误显示在对应输入框下方；
* 只有校验通过才返回结果并调用 `PATCH /api/v1/devices/{id}`；
* 服务端失败时由账户页显示 `_error`（原有逻辑未改），**不影响当前登录状态**。

### 3.3 顺带修掉的 `setState() called after dispose()`

弹窗返回后调用方会碰自己的 State，所以给三处加了 `mounted` 保护：
`asset_library_page._run()`、`account_sync_page._editCurrentDevice()`、
`usage_stats_page._reload()`。它们在"父页面先被销毁、弹窗随后关闭"时会直接返回。

## 4. 全项目审计结论

按需求搜索了 `showDialog` / `showModalBottomSheet` / `TextEditingController` /
`FocusNode` / `GlobalKey<FormState>`：

| 位置 | 结论 |
|---|---|
| `asset_library_page._askFileImportForm` | ❌ 命中（已修） |
| `account_sync_page._editCurrentDevice` | ❌ 命中（已修） |
| `usage_stats_page._promptText` | ❌ 命中（已修，同一形状） |
| `ai_access_card._askKeyName` | ✅ 本来就是正确写法：`_nameController` 是 **State 字段**，在 `State.dispose()` 里销毁 —— 所有者本来就对，无需改动 |
| `account_sync_page` 登录表单（`_baseUrl` / `_email` / `_password` / `_proxy*`） | ✅ State 字段，随页面销毁；不是弹窗内控制器 |
| `asset_library_page._pathController` | ✅ 同上 |
| 其余 `showDialog`（确认框、分类选择框） | ✅ 不含任何控制器 |
| `FocusNode` / `GlobalKey<FormState>` | lib/ 下无其它使用；`DeviceEditDialog` 内的 `Form` key 属于弹窗 State |

审计不是一次性的：`test/dialog_lifecycle_test.dart` 里固化了一条**静态检查**，
禁止"在调用方创建控制器 → await 弹窗 → 再 dispose"这个形状再次出现（见 §5）。

### 5.1 这组测试确实抓得住这个 bug（反向实验）

为确认不是"空跑"，临时把 `DeviceEditDialog._submit()` 改成
**在 `Navigator.pop` 之前**先 `_name.dispose(); _model.dispose();`，重跑：

```
'_dependents.isEmpty': is not true.
pos 12: '_dependents.isEmpty': is not true.>
弹窗关闭过程中不应出现任何 FlutterError（含 _dependents.isEmpty 断言）
00:03 +10 -12: Some tests failed.
```

* 复现出的断言与真机**完全一致**（含 `pos 12`）；
* 22 项里 **12 项立刻失败**；
* 实验已回退，当前代码重新全绿。
