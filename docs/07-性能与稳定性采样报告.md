## 3. 采样方法

### 3.1 为什么从外部采样

应用**内置**了 `PerfSampler`（控制面板 → 诊断页有开始/停止按钮，停止后导出 CSV + JSON），
它用 `GetProcessTimes` / `GetProcessMemoryInfo` / `GetProcessHandleCount` 采自己的进程。

本次验收是在**无人值守**条件下做的，无法点击 GUI 按钮，因此改用**外部采样器**：
同样的三个 Win32 数据源，从外部按 PID 读取被测进程。

> **两者读的是同一组内核计数器**（外部采样用 `Get-Process` 的 `CPU` / `WorkingSet64` /
> `Handles`，它们分别由上述三个 API 提供），因此数据可比。

外部采样器的另一个好处是**更严格**：采样进程与被测进程隔离，采样本身不会进入被测进程的地址空间。

### 3.2 采了哪些量

| 列 | 含义 |
|---|---|
| `working_set_mb` | 工作集（任务管理器「内存」列的口径） |
| `private_mb` | 私有提交（更敏感，能更早暴露增长） |
| `handles` | 句柄数（泄漏信号） |
| `threads` | 线程数 |
| `cpu_total_s` | 进程累计 CPU 时间（内核态 + 用户态） |
| `cpu_pct_one_core` / `cpu_pct_machine` | 由相邻两点 CPU 增量 ÷ 时间增量算出 |

## 5. 关键发现：一个由真实用户操作引起的台阶

数据不是一条平线，中间有一个明显的台阶。**它被日志完整解释清楚了**：

```
19:00:32.167 [INFO] petlife.window: 窗口设置已应用: 置顶=true ...
19:00:32.183 [INFO] petlife.window: 切换到控制面板模式 1180x760
19:00:35.621 [INFO] petlife.window: 窗口设置已应用: 置顶=true ...
19:00:35.621 [INFO] petlife.window: 切换到桌宠模式
```

即 **19:00:32 打开控制面板（1180×760）、19:00:35 切回桌宠**——一次真实的人为操作。
采样数据里对应的是 `t=501s (19:00:33)` 的那一跳：

| 指标 | 切换前 | 切换后 |
|---|---|---|
| 私有提交 | 85.30 MB | **139.09 MB**（+53.79） |
| 工作集 | 83.91 MB | **97.52 MB**（+13.61） |
| 句柄 | 398 | **417**（+19） |
| 累计 CPU | 1.891 s | 2.000 s（+0.109 s） |

**原因**：控制面板是整个应用的**大头**——5 个页面（素材库 770 行 / 状态映射 454 行 /
状态调试器 400 行 / 设置 309 行 / 诊断 333 行）一次性构建进 `TabBarView`，
还要把窗口从 512×384 放大到 1180×760。这一跳是**一次性分配**，不是增长。

因此把 30 分钟切成两段看：

### 阶段 A：纯空闲稳态（t 0 → 491 s，50 个采样点）

| 指标 | 最小 | 最大 | 平均 | 末值 |
|---|---|---|---|---|
| 工作集 (MB) | 80.61 | 83.91 | 82.87 | 83.91 |
| 私有提交 (MB) | 84.13 | 86.27 | 85.13 | 85.30 |
| 句柄数 | 389 | 402 | 396 | 398 |
| 线程数 | 38 | 44 | 39 | 39 |
| 累计 CPU | — | — | — | 1.812 → 1.891（**8 分钟只用 0.078 s**） |

### 阶段 B：面板开合之后（t 501 → 1796 s，129 个采样点）

| 指标 | 最小 | 最大 | 平均 | 末值 |
|---|---|---|---|---|
| 工作集 (MB) | 83.77 | 97.93 | 93.60 | **84.57** |
| 私有提交 (MB) | 105.06 | 142.50 | 138.01 | **105.06** |
| 句柄数 | 406 | 417 | 409 | **406** |
| 线程数 | 38 | 43 | 40 | 43 |
| 累计 CPU | — | — | — | 2.000 → 2.359（**21 分钟只用 0.359 s**） |

**阶段 B 内部还在往下走，不是往上走**：

```
工作集：前半段均值 94.62 MB  →  后半段均值 92.60 MB   （↓2.02）
私有  ：前半段均值 140.79 MB →  后半段均值 135.28 MB  （↓5.51）
```

并且 **19:21:07 出现一次明确的内存回收**：

```
t=1726  19:20:57   WS 93.58  Priv 138.34  hnd 406
t=1736  19:21:07   WS 83.77  Priv 138.34  hnd 406   ← 工作集回落 9.81 MB
t=1746  19:21:17   WS 84.57  Priv 105.06  hnd 406   ← 私有提交回落 33.28 MB
...直到结束保持 84.57 / 105.06 / 406
```

**这说明控制面板占用的内存最终被释放了**（面板 Widget 销毁 + Dart GC 回收），
不是「只增不减」。末值相对启动基线只多 **+3.85 MB 工作集 / +18.79 MB 私有提交**，
与「Flutter 引擎预热后常驻的着色器 / 字体 / 管线缓存」量级相符。

## 6. 判定

### 6.1 内存泄漏

| 判定项 | 阈值 | 实测 | 结论 |
|---|---|---|---|
| 后 1/3 均值 vs 前 1/3 均值 | > +20 MB 且 > 1.2× | +7.34 MB（85.15 → 92.50） | **未触发** |
| 阶段 B 前后半段趋势 | 应上升 | **下降** 2.02 MB（工作集） | 反向，排除泄漏 |
| 末值 vs 峰值 | — | 84.57 vs 97.93（回落到峰值以下 13.36 MB） | 已回收 |
| 末值 vs 基线 | — | +3.85 MB | 常驻缓存量级 |

> 注意：`+7.34 MB` 这个看起来像「增长」的数字**只是那一次面板开合台阶被算进了前后 1/3 的均值差**。
> 剔除该事件后（阶段 B 内部）趋势是**向下**的。因此判定：**无内存泄漏**。

### 6.2 句柄泄漏

净变化 **+13**（393 → 406），峰值 417，且**在 19:20:37 从 410 降到 406 后不再增长**。
+13 全部来自那一次面板开合（+19 后回落到 +8，之后稳定）。判定：**无句柄泄漏**。

### 6.3 线程泄漏

38 ~ 44 之间波动，无单调增长。判定：**无线程泄漏**。

### 6.4 CPU

| 指标 | 值 |
|---|---|
| 平均（单核口径） | **0.031%** |
| 平均（整机 12 核口径） | **0.0026%** |
| 峰值（单核口径） | **3.275%**（出现在窗口形态切换瞬间） |
| 30 分钟累计 | **0.547 秒** |

空闲态 CPU 基本为 0：绝大多数采样点的 `cpu_pct_one_core` 是 `0.000`。
这在「静态占位图、无素材导入」的前提下是符合预期的——没有动画在逐帧重绘。

## 7. 局限（必须知道）

1. **本次未导入素材**，桌宠显示的是**静态内置占位图**。因此本报告**没有覆盖**
   「13 个 WebP 动态图持续播放」时的 CPU 占用与解码内存。
   动画解码路径的正确性由 37 个测试覆盖（`webp_container_test.dart` 对全部 13 个文件断言
   256×192 / 多帧 / 带透明通道），但**其持续渲染开销尚未实测**。
2. 30 分钟短测不足以暴露「小时级」才显现的缓慢增长。若需要 2 小时长测，
   把 `SOAK_DURATION` 改成 `7200` 重跑即可（方法见 `06-构建运行手册与开发环境.md` §7.2）。
3. 采样期间机器上有其他负载（构建工具链进程），CPU 百分比存在轻微噪声；
   但由于采的是被测进程自己的内核计数器，噪声不影响其 CPU 时间的准确性。

## 8. 复现方法

```powershell
# 1. 启动被测程序，拿到 PID
cd build\windows\x64\runner\Release
.\petlife.exe
Get-Process petlife | Select-Object Id

# 2. 外部采样 30 分钟，每 10 秒一点
$env:SOAK_PID='<上一步的 Id>'
$env:SOAK_OUT='<输出目录>'
$env:SOAK_INTERVAL='10'
$env:SOAK_DURATION='1800'
& '<脚本目录>\soak_sampler.ps1'
```

```bash
# 3. 汇总
python analyze_soak.py <输出目录>/soak_samples.csv <输出目录>/soak_analysis.json
```
