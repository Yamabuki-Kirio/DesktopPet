## 2. 环境变量（每次新开 shell 都要设）

```bash
export PATH="/c/src/flutter/bin:/c/src/flutter/bin/cache/dart-sdk/bin:$PATH"
export PUB_CACHE='C:\Users\Administrator\AppData\Local\Pub\Cache'
```

### 为什么必须设 `PUB_CACHE`

Flutter 包装脚本在首次运行时会执行一次同步的 `dart pub cache preload`，把 **186 个内置 tarball** 全量展开。在受限网络下这一步会**挂起约 15 分钟**。

显式设置 `PUB_CACHE` 后，Flutter 认为缓存已就绪，**跳过整个 preload 流程**，`pub get` 从 ~15 分钟降到 **约 7 秒**。

### 为什么加 `--no-version-check`

Flutter 每次运行会去 GitHub 做一次版本检查，在本网络下会挂起。加 `--no-version-check` 直接跳过。

## 3. 依赖安装

```bash
flutter --no-version-check pub get
```

**必须用 `flutter pub get`，不能用 `dart pub get`。** 原因：`windows/flutter/generated_plugins.cmake`、`generated_plugin_registrant.{cc,h}` 以及 `windows/flutter/ephemeral/.plugin_symlinks/` 下的插件软链接**只有 Flutter 工具会生成**。缺了这些文件，CMake 配置阶段会直接报：

```
include could not find windows/flutter/generated_plugins.cmake
```

## 4. `pubspec.yaml` 里那段 `hooks` 是必需的

```yaml
hooks:
  user_defines:
    sqlite3:
      source: system
      name_windows: sqlite3
```

**背景**：SQLite 的 native assets 构建钩子默认会从 **GitHub Releases** 下载预编译的 `sqlite3.x64.windows.dll`。在只放行 sqlite.org / pub 镜像的受限网络下会失败（实测 **502 Bad Gateway**）。

**改法**：`source: system` 让钩子只登记「运行时按名字查找」，改由 `sqlite3_flutter_libs` 的 Windows CMake 脚本**从 sqlite.org 编译**出 `sqlite3.dll` 并随应用打包。

> ⚠️ **`name_windows` 千万不要带 `.dll` 后缀。**
> native assets 运行时会自动补平台后缀。写成 `sqlite3.dll` 会变成 **`sqlite3.dll.dll`**，启动时报：
> `Failed to load dynamic library 'sqlite3.dll.dll' (error code 126)`
> 这个坑已在真机验证过。

## 5. 静态检查与测试

### 5.1 analyze —— 必须加 `--no-pub`

```bash
flutter --no-version-check analyze --no-pub
```

期望输出：`No issues found!`（本机实测 **7.8 s**，`exit=0`）

> ⚠️ **不要省掉 `--no-pub`。** 不带它时 analyze 会先隐式跑一次 `pub get`，
> 而 `pub get` 会**重建** `.plugin_symlinks`、在建第一个链接时撞上 §6.1 的已知异常而中断。
> 后果不只是 analyze 失败（`exit=1`），**它会先把已有的软链接目录清空**，
> 只留下报错前的那一个条目，从而破坏后续构建的前置条件。
> 本次就该踩了一次：`flutter analyze`（无 `--no-pub`）之后 `.plugin_symlinks/` 里只剩 `file_picker` 一个。

`pub get` 本身的输出看起来是完全正常的：

```
Resolving dependencies...
Downloading packages...
* window_manager 0.5.2 (was 0.5.2)
...
Changed 82 dependencies!
Flutter failed to create a link at "...\.plugin_symlinks\file_picker" ...
PathNotFoundException: Cannot create link ... (OS Error: 系统找不到指定的文件。, errno = 2)
```

所有版本都 `was X == X`（未真正变化），**失败点是建链接那一步，不是依赖解析**。

### 5.2 test —— 关键是「回环必须绕过代理」

```bash
export NO_PROXY="127.0.0.1,localhost,::1"
flutter --no-version-check test
```

**原理**：`flutter test` 通过 **localhost 的 WebSocket** 与 `flutter_tester` 进程通信。若环境里存在 HTTP 代理（本机为 `HTTP_PROXY=http://127.0.0.1:59055`）且没有 `NO_PROXY`，这个本地回环连接会被路由到代理上，直接失败：

```
Unable to connect to flutter_tester process: WebSocketException
```

实测**两种做法都能通过**：

| 做法 | 结果 |
|---|---|
| 摘掉代理（`unset HTTP_PROXY ...`）+ 设 `NO_PROXY` | 全绿 |
| **保留代理 + 设 `NO_PROXY`** | **234 / 234 全绿**（+1 跳过） ✅ **推荐** |

**推荐第二种**：摘掉代理会让后续任何需要联网的 pub 操作**静默挂起**（没有报错、没有输出）。
保留代理 + 只让回环直连，才是既不挂起、又能跑测试的配置。

> **排查提示（已定位）**：`flutter analyze` 曾出现"命令迟迟不返回"的现象，真实原因有三条，
> 都不是崩溃：
> 1. 外层 PowerShell 包装没有正确传递 Flutter 的退出码，看起来像在等待；
> 2. 该次分析确实**有 2 处 lint 报错**（`e2e_real_server_test.dart` 里的字符串插值），
>    而不是"卡住"；
> 3. 在受限沙箱里运行时，Flutter 包装脚本可能无法写
>    `C:\src\flutter\bin\cache\engine.stamp`，此时会直接报
>    `Unable to determine engine version...`——**在沙箱外运行即可**。
>
> 修掉那 2 处 lint 后，本机实测：`No issues found! (ran in 9.2s)`，退出码 `0`。
> 结论：**不要因为"没有输出"就无限等待**，先把退出码与 stderr 拿出来看。

## 6. 构建 Windows x64

### 6.1 插件软链接（受限环境下的必要步骤）

Flutter 工具在 `pub get` 时会调用 `Link.createSync` 建插件软链接。在本沙箱里该调用会抛：

```
PathNotFoundException (OS Error 2, 系统找不到指定的文件)
```

**关键在于：链接实际上已经建好了**，抛异常的是 API 本身。这是个「假失败」，
但 Flutter 把它当致命错误处理，于是**循环在第一项就中断**——
症状是 `.plugin_symlinks/` 里只剩下报错前的那一个条目，其余全部缺失。

因此需要一个帮手脚本（`.workbuddy/tmp/link_plugins.dart`）把所有链接补齐：

```bash
cd petlife
dart "C:/Users/Administrator/WorkBuddy/DesktopPet/.workbuddy/tmp/link_plugins.dart"
```

脚本行为：

1. **从 `.flutter-plugins-dependencies` 的 `plugins.windows[*]` 读取插件清单**（权威来源，
   Flutter 工具就是按它建链的）；
2. 再与 `windows/flutter/generated_plugins.cmake` 取**并集**（后者只列带原生代码的插件，
   用作兜底与一致性校验）；
3. 目标路径优先取 `.flutter-plugins-dependencies` 给出的绝对路径，
   缺失时才回退到 `.dart_tool/package_config.json` 解析
   （两者的路径都由 pub 工具生成，因此**换 pub 镜像或升版本都无需改脚本**）；
4. 逐个建链，`createSync` 的异常按已知问题吞掉；
5. 逐个**校验**「链接可解析 且 能列出目录内容」，只有同时满足才算 OK；
6. 最后单独校验「CMake 会 `add_subdirectory` 的插件是否都有链接」；
7. 全部就绪时 `exit 0`。

本机输出的待处理插件为 **7 个**：

| 插件 | 归类 |
|---|---|
| `screen_retriever_windows` | 有原生代码（`FLUTTER_PLUGIN_LIST`） |
| `sqlite3_flutter_libs` | 有原生代码（`FLUTTER_PLUGIN_LIST`） |
| `tray_manager` | 有原生代码（`FLUTTER_PLUGIN_LIST`） |
| `window_manager` | 有原生代码（`FLUTTER_PLUGIN_LIST`） |
| `jni` | 有原生代码（`FLUTTER_FFI_PLUGIN_LIST`） |
| `file_picker` | **Dart-only**（`dartPluginClass`，无 `windows/` 目录） |
| `path_provider_windows` | **Dart-only**（`dartPluginClass`，无 `windows/` 目录） |

> ⚠️ **只按 `generated_plugins.cmake` 补链是不够的** —— 这是本项目实际踩过的坑
> （缺陷 D-02）。`file_picker` 与 `path_provider_windows` 只有 Dart 实现，
> 不会出现在 CMake 清单里，**但 Flutter 工具仍然要为它们建软链接**。
> 漏建时的报错是：
>
> ```
> Flutter failed to create a link at "...\.plugin_symlinks\path_provider_windows"
> PathNotFoundException: Cannot create link (OS Error: 系统找不到指定的文件。, errno = 2)
> build_exit=1
> ```
>
> 注意这个报错会**伪装成上面那个「假失败」**，很容易误判为「本机已知问题，忽略即可」——
> 但它的根因完全不同：目标**确实不存在**。判别方法：
> 看报错里的路径后缀，假失败的路径是已存在的包目录，真缺失则是漏建的插件名。
> 修法就是让脚本按 `.flutter-plugins-dependencies` 取并集（现已如此）。

完成后再加 **`--no-pub`** 构建，跳过 Flutter 内部的重建步骤：

```bash
flutter --no-version-check build windows --release --no-pub
```

## 8. 已知环境噪声（不影响交付物）

| 现象 | 原因 | 处理 |
|---|---|---|
| `flutter doctor` 崩溃 | 沙箱把 `reg.exe` / `wmic.exe` 列为黑名单，而 doctor 要调它们 | 忽略。工具链是否齐备直接看磁盘上的 VS / Windows SDK 即可 |
| 每条命令都打印 `shim/shell-runtime-bash-env.sh: line 3: dirname: command not found` | shell 运行时包装脚本的噪声 | 无害，可忽略 |
| `flutter pub get` 后插件软链接报 `OS Error 2` | 见 §6.1 | 用 `link_plugins.dart` + `--no-pub` 绕过 |
| 受管 shell 的 `PATH` 偶尔丢失 Git coreutils | 沙箱环境问题（`ls` / `dirname` 找不到） | 在命令前显式 `export PATH="/c/Users/Administrator/.workbuddy/binaries/PortableGit/versions/1.2.0/usr/bin:..."` |
| PowerShell 工具不回显 stdout | 工具输出通道问题（命令本身正常执行） | 让 PowerShell **把结果写进文件**，再用 Read 读取 |

## 9. 常用命令速查

```bash
# 一次性准备
export PATH="/c/src/flutter/bin:/c/src/flutter/bin/cache/dart-sdk/bin:$PATH"
export PUB_CACHE='C:\Users\Administrator\AppData\Local\Pub\Cache'
export HTTP_PROXY='http://127.0.0.1:59055'      # 需要联网的 pub 操作要靠它
export HTTPS_PROXY='http://127.0.0.1:59055'
export NO_PROXY="127.0.0.1,localhost,::1"       # 但回环必须直连（flutter_test 依赖）

flutter --no-version-check pub get               # 之后 .plugin_symlinks 会被清空，见下

# 质量门
```

### 10.4 两个已踩过的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| embeddable Python 忽略脚本目录 | `ModuleNotFoundError: No module named 'app'` | 在 `python312._pth` 里加 `..` |

## 11. 客户端 ↔ 服务端真实联调

一条命令跑完整条链路（自动起服务端 → 迁移 → 5 个阶段 → 停服务端）：

```powershell
cd petlife
$env:NO_PROXY = 'localhost,127.0.0.1,::1'
powershell -ExecutionPolicy Bypass -File tools\e2e_client_sync.ps1
```

脚本行为：

1. 用 `server/.python` 跑 Alembic 迁移（**必须先 `Push-Location server`**，
   因为 `alembic.ini` 在 `server/` 下）；
2. 起 uvicorn（端口 `8010`），把**服务端 stdout 写文件**（`build\e2e\uvicorn.log`），
   不要用管道接——管道缓冲区写满会让服务进程阻塞；
3. 依次对 5 个阶段各跑一次 `flutter test test/e2e_real_server_test.dart`，
   用 `PETLIFE_E2E_STAGE` 指定阶段，用 `PETLIFE_E2E_BASE_URL` 指定地址；
4. 每个阶段之间**按需起停服务端**（`offline` 阶段就是要它停着）；
5. 任一阶段失败就 dump uvicorn 日志。

阶段与覆盖范围：

| 阶段 | 服务端 | 覆盖 |
|---|---|---|
| `online` | 运行 | 注册 / 登录 / 设备注册 / 产生活动记录 / 立即同步 / 统计一致 / 重复同步不重复 |
| `offline` | **停止** | 本地采集继续、同步进入 `waitingForNetwork`、数据不丢 |
| `recover` | 运行 | 自动补传、统计增长 |
| `revoked` | 运行 | 设备被撤销 → `needsReauthentication`，本地采集不停 |
| `signout` | 运行 | 凭据被删除、本地数据保留 |

5 个阶段共享同一个 `build\e2e\e2e.db`（等价于"关掉客户端再打开"）。
**为什么不能写成单个测试**：需要在两次客户端运行之间起停服务端，
而单个 `flutter test` 进程做不到。

### 11.1 三个坑（已踩过）

| 坑 | 现象 | 解法 |
|---|---|---|
| PowerShell 5.1 用 GBK 读 `.ps1` | 无 BOM 且含中文注释时解析器直接崩（`Unexpected token`） | 脚本保持**纯 ASCII**（与 `alembic.ini` 同一教训） |
| **PS 5.1 把原生命令的 stderr 当致命错误** | 脚本里 `$ErrorActionPreference='Stop'` + `alembic`/`flutter test` 往 stderr 写 INFO/警告 → `NativeCommandError`，**命令其实成功了脚本却中断** | 在两处原生命令调用外**局部**把 `$ErrorActionPreference` 设为 `Continue`，改用 `$LASTEXITCODE` 判定成败（已在 `tools/e2e_client_sync.ps1` 修好） |
| 用非 UUID 字符串当记录 id | 真实服务端返回 `422`（`ActivitySegmentIn.id` 是 `uuid.UUID`） | 用例里生成合法 UUID；运行时由 `Ids.segment()` 保证 |

## 12. 代理（Clash / HTTP 代理）

长时间挂 Clash 的机器上，PetLife 默认会**自动检测 Windows 系统代理**并使用它，
不需要额外配置。配置入口在控制面板 →「账户与同步」→「网络连接」。

### 12.1 配置面

| 模式 | 用途 |
|---|---|
| 自动检测（默认） | 读 Windows 当前用户代理；没有就直连 |
| 跟随 Windows 系统代理 | 同上，但检测不到会**明确报错**（适合确定自己开了 System Proxy 的人） |
| 手动 HTTP 代理 | 直接填 `地址:端口`（Clash 的 HTTP/Mixed Port，例如 `127.0.0.1:7877`） |
| 直接连接 | 忽略一切代理设置 |

配置存在 `local_settings` 的 `sync.proxy*` 键里；**代理密码不在其中**，
它走 `CredentialStore`（`PetLife:proxy`）。详见 `19-隐私与安全说明.md` §7.5。

### 12.2 Clash 侧要点

- **Clash 必须开启 System Proxy**（写进注册表，PetLife 才检测得到），
  或者在 PetLife 里选手动 HTTP 代理并填 HTTP/Mixed Port；
- **不要求开启 TUN**；
- **SOCKS 端口不能当 HTTP 代理用**。只开了 SOCKS5 时请改用 **Mixed Port**
  （Clash 里 HTTP 与 SOCKS 共用一个端口）；
- 代理地址一般是 `127.0.0.1`，端口以 Clash 界面显示的为准。

### 12.3 排错顺序

1. 点「检测系统代理」→ 看是否读到 `ProxyServer`（读不到说明 Clash 的 System Proxy 没开）；
2. 点「测试代理」→ 区分 *连不上代理* / *代理要求认证(407)* / *隧道被拒*；
3. 点「测试服务端」→ 再加上 TLS 握手与 `/health`；
4. 全绿后再点「保存并重新连接」，页面上的「当前实际使用」会显示最终出口。

错误文案是**分阶段**的（`proxyConnectionRefused` / `proxyAuthenticationRequired` /
`proxyConnectRejected` / `tlsHandshakeFailed` / `serverUnreachable` / `healthCheckFailed`），
不会只给一句"握手失败"。

### 12.4 PAC / WPAD

**本轮不支持**。检测到时会明确提示"暂不支持 PAC，已退回直连"，
并要求改用 System Proxy 或手动填写 —— 不会静默把它当成直连（那样用户会误以为代理生效了）。

### 12.5 在受限沙箱里跑 Flutter 命令

若 Flutter 包装脚本报：

```
Set-Content : 对路径"C:\src\flutter\bin\cache\engine.stamp.tmp.xxxx"的访问被拒绝
Error: Unable to determine engine version...
```

说明当前 shell 被限制了写入 `C:\src\flutter\bin\cache\`，
`flutter analyze` / `flutter test` / `flutter build` 都会**没有任何输出**地失败
（看起来像"卡住"，其实起都没起来）。

**已在 Trae 里实测有效的解法**：Settings → Permission & Approval → Custom Configuration，
放行这两个路径，之后三条命令都能直接跑通：

```
C:\src\flutter\**                              # flutter.bat 的 engine.stamp、PUB_CACHE
C:\Users\Administrator\AppData\Local\.dartServer\**   # analyze 用的分析服务临时目录
```

> 注意：**审批（requirements_approval）不等于沙箱放行**。审批只决定"要不要先问你"，
> 不会改变沙箱的文件白名单 —— 提权跑仍然会因为写不了 `engine.stamp` 而静默失败。
>
> 另外 `flutter analyze` 有时"久久不返回"：先看**退出码与 stderr**，不要无限等待。

### 12.6 已修的两个真实缺陷（代理支持引入）

| 缺陷 | 现象 | 修法 |
|---|---|---|
| `ApiClient` 写请求体没设 `Content-Length` | Dart 退化成 `Transfer-Encoding: chunked`；定长解析的中间件/替身会读到 `1D\r\n{...}` 这类 chunk 头 | 显式 `request.contentLength = payload.length` + `request.add(payload)` |
| 假代理不理解 chunked | 把 chunk 头当 body 原样转发，下游只报一个莫名其妙的 JSON 解析错误 | 遇到 `Transfer-Encoding: chunked` **明确回 501**，并计入 `chunkedRequests` |
