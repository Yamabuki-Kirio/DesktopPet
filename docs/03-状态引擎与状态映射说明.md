# 03 · 状态引擎与状态映射说明

> 核心设计：**系统状态**与素材里作者写的**原始情绪名**是两个独立概念。
> 素材侧可以有任意情绪（`Angry` / `Bench_Thinking` / `Nod` …），系统侧只认 11 个状态，
> 两者通过 `state_mappings` 表由用户绑定。

## 1. 11 个系统状态与默认优先级

数值越大越优先。用户可以在状态映射页覆盖优先级。

| 优先级 | 状态 | wireName | 中文 | 最短展示 | 备注 |
|---:|---|---|---|---|---|
| 100 | `error` | `error` | 错误 | 0 | **紧急**：可立即打断当前动画 |
| 95 | `manual` | `manual` | 手动锁定 | ∞ | **紧急 / 锁定**：直到用户解除，自动状态无法顶掉 |
| 90 | `concerned` | `concerned` | 担忧 | 15 s | |
| 80 | `tired` | `tired` | 疲惫 | **5 min** | 最长的保持时间 |
| 70 | `happy` | `happy` | 开心 | 10 s | |
| 60 | `gaming` | `gaming` | 游戏 | 15 s | 应用派生 |
| 50 | `focused` | `focused` | 专注 | 15 s | 应用派生 |
| 40 | `social` | `social` | 社交 | 15 s | 应用派生 |
| 30 | `entertained` | `entertained` | 娱乐 | 15 s | 应用派生 |
| 20 | `away` | `away` | 离开 | 15 s | 应用派生 |
| 0 | `defaultState` | `default` | 默认 | 15 s | 最终兜底状态 |

**应用派生状态**（`focused` / `gaming` / `social` / `entertained` / `away`）额外受「前台应用需稳定 10 秒」规则约束。

`wireName` 是**持久化 / API 的稳定标识**，永远用 snake_case 小写英文；UI 展示用 `descriptionZh`。这样以后加语言、改文案都不会影响数据库里的值。

## 2. 触发来源（`StateTrigger`）

| 取值 | 标签 | 阶段 |
|---|---|---|
| `init` | 启动初始化 | 0 |
| `foregroundApp` | 前台应用 | 1 |
| `idle` | 空闲检测 | 1 |
| `lockScreen` | 锁屏 | 1 |
| `manual` | 用户手动 | 0 |
| `debugger` | 状态调试器 | 0 |
| `error` | 错误事件 | 0 |
| `fallback` | 回退 | 0 |

阶段 0 真实可用的触发源是 **`debugger`（状态调试器）/ `manual`（手动锁定）/ `init` / `fallback`**；
`foregroundApp` / `idle` / `lockScreen` 三条链路已在引擎里就位，等阶段 1 接上真实信号即可，**引擎本身不关心信号从哪来**。

## 3. 防抖决策（`StateDebouncer`）

`StateDebouncer` 是一个**纯函数对象**：不持有计时器、不访问数据库，只接收「当前状态 + 时间戳 + 请求」并返回一个决策。因此它可以被单测穷举覆盖（`test/state_engine_test.dart`）。计时器由 `DefaultStateEngine` 负责。

决策有三种：

| 决策 | 含义 |
|---|---|
| `ApplyNow` | 通过全部规则，附带「是否应等当前动画播完一轮」 |
| `DeferUntil(at, reason)` | 推迟到某时刻再尝试 |
| `RejectChange(reason)` | 直接拒绝 |

判定顺序（**顺序即优先级**）：

```
1. manual 锁定检查
   当前是 manual 且请求不是 manual 且 force=false  → RejectChange

2. 同状态重复请求
   请求状态 == 当前状态 且 无 manualAssetId 且 非 immediate → RejectChange
   （作用：同一张图片绝不反复重新加载、不重启动画）

3. 前台应用需稳定 10 秒
   请求状态是应用派生 且 稳定时长 < 10s 且 force=false → DeferUntil

4. 当前状态最短展示时长
   已展示 < currentState.minHoldMs → DeferUntil

5. 快速切换抑制窗口（400 ms）
   —— 这一条对 force 模式**同样生效**
   （作用：快速切换窗口时不得连续闪烁，即验收第 15 项）
```

**为什么第 5 条要无视 `force`**：`force` 用于让调试器能触发全部 11 个状态，但如果连闪烁保护也被 `force` 绕过，就无法验证「快速切换不闪烁」了。

**为什么 `force` 存在**：`default` 的优先级是 0，若严格按优先级演算，它在 `error`（100）之后会被永久挡住，验收第 14 项（能触发全部 11 个状态）无法通过。因此调试器使用 `force=true`，而阶段 1 接入真实统计时**自动切换一律 `force=false`**。

## 4. 5 级回退链（`FallbackChain`）

当某个状态需要一张图时，按**严格顺序**尝试以下 5 级，第一级命中即停：

| 级别 | `FallbackLevel` | 依据 |
|---:|---|---|
| 1 | `stateAsset` | 目标状态**指定的具体图片**（`state_mappings.asset_id`）；manual 状态优先使用用户临时指定的图片 |
| 2 | `stateEmotion` | 目标状态**指定的情绪**（`state_mappings.emotion_name`，按情绪名大小写不敏感匹配） |
| 3 | `characterDefault` | 角色默认图片（`character_models.default_asset_id`） |
| 4 | `firstValidAsset` | 角色**第一个**有效素材 |
| 5 | `builtinPlaceholder` | **内置占位图**（`asset == null`） |

**每次解析都会产出一条 `reason` 文本**并写入日志与状态调试器，例如：

- `命中状态 focused 的指定图片（2 个候选中按权重选中 Thinking/1）`
- `状态 tired 无映射，回退到角色默认图片`
- `角色没有任何可用素材`

这是需求「回退素材原因必须记录」的落点。

### 加权随机

同一级别存在**多个候选**时，按 `state_mappings.weight` 做加权随机选择（权重 ≤ 0 视为 0；总权重为 0 时取第一个）。因此同一个状态可以配置多张图并控制出现频率。

### 候选过滤

`FallbackChain.resolve` 接收的 `renderableAssets` 必须是**已过滤**的可用素材（`enabled = 1` **且** `validation_status = 'valid'`）。已删除或已禁用的素材会在第 1 级里被**静默跳过**（不报错、不回退失败），避免映射表里残留的失效 ID 影响渲染。

## 5. 默认映射的自动生成

导入素材后，`DefaultMappingSeeder` 会按「建议情绪表」自动生成一组 `state_mappings`。**用户无需任何手工配置**就能看到多状态效果。

| 系统状态 | 建议情绪 |
|---|---|
| `default` | Cheerful |
| `focused` | Thinking、Bench_Thinking |
| `gaming` | Excited、Confident |
| `social` | Cheerful、Nod |
| `entertained` | Excited、Surprised |
| `tired` | Disheartened、Bench_Exasperated |
| `away` | Thinking |
| `happy` | Cheerful、Excited、Nod |
| `concerned` | Worried |
| `error` | Shocked、Angry |
| `manual` | **（刻意留空）** 必须由用户显式指定图片 |

规则细节：

- 匹配**按情绪名**（大小写不敏感），**不写死任何文件名、不绑定任何角色**；
- 每个状态**最多 3 个候选**（`maxCandidatesPerState`），避免情绪特别多时把界面撑爆；
- 同一情绪下多个变体**只取第一个**，避免候选里出现视觉重复；
- 只匹配 `isRenderable`（可用）的素材，避免建议指向已损坏文件；
- **已存在映射的状态不会被覆盖**（由调用方保证），用户改过的配置不会在重新导入时被冲掉；
- `default` 状态**保证有图**：即使没有任何情绪命中，也会把第一个有效素材绑给它，避免首次启动就显示占位图；
- 生成的结果就是**普通的 `state_mappings` 记录**，用户可以随意修改或清空。

对 Ace Attorney / Maya 的实测结果（13 个情绪全部命中，无需手工配置）见 `08-Ace Attorney 扫描结果与索引示例.md` §5。

## 6. 状态快照与事件

引擎对外暴露两样东西：

| 出口 | 类型 | 用途 |
|---|---|---|
| `snapshots` | `ValueListenable<StateSnapshot>` | UI 直接监听重建（当前状态、当前角色、当前素材、manual 锁定的图片、回退级别与原因） |
| `events` | `Stream<StateChangeEvent>`（广播） | 渲染层订阅，做淡入淡出与「等当前动画播完一轮」 |

`StateChangeEvent` 关键字段：`from` / `to` / `trigger` / `reason` / `waitForAnimationCycle` / `at`，
以及 `isCrossFade => from != to`（同状态换图不算 cross-fade）。

## 7. 引擎接口（`StateEngine`）

| 方法 | 作用 |
|---|---|
| `start(ownerId, characterId)` | 启动引擎并绑定默认角色 |
| `setCharacter(characterId)` | 切换角色（**保留**用户对状态的锁定） |
| `restore(ownerId, characterId, assetId)` | 启动后恢复上次的角色与表情（验收第 18 项） |
| `requestState(request)` | 请求切换状态（走防抖） |
| `lockManual(assetId, reason)` | 用户手动锁定到某张图片（`manual` 状态） |
| `releaseManual()` | 解除手动锁定，恢复自动切换 |
| `refresh()` | 重新解析当前状态应显示的素材（映射被改 / 素材启用禁用后调用） |
| `dispose()` | 释放资源 |

## 8. 状态映射页能做什么

`ui/pages/state_mapping_page.dart`（454 行）提供：

- 按**系统状态**分组展示当前绑定（按具体图片 / 按情绪两种模式）；
- 添加、删除、修改映射；
- 调整 `weight`（加权随机）与 `priority`（优先级覆盖）；
- 一键**重新生成建议映射**；
- 修改后立即 `stateEngine.refresh()`，桌宠当场换图，无需重启。

## 9. 状态调试器能做什么

`ui/pages/state_debugger_page.dart`（400 行）提供：

- 手动触发**全部 11 个状态**（`force=true`，验收第 14 项）；
- 显示当前状态、触发来源、触发原因、回退级别与原因；
- 显示防抖判定结果（为什么被推迟 / 被拒绝）；
- 连续快速切换用于验证「不闪烁」（验收第 15 项）；
- 内嵌实时性能数据（监听 `PerfSampler`）。
