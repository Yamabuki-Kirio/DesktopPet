# 02 · 素材规范与导入校验

> 目标：**直接兼容用户已有的素材文件夹**，不要求改名、不要求写配置文件、不修改原始文件。

## 1. 一句话规则

> 把图片放进一个文件夹，文件夹名就是「作品包名」；文件名写成 `角色名_情绪名_可选序号.扩展名`，导入即可。
> 命名不合规的文件不会让导入失败，只会落到 `default` 情绪。

## 2. 支持的格式

| 格式 | MIME | 允许的扩展名 | 可动 | 说明 |
|---|---|---|---|---|
| WebP | `image/webp` | `.webp` | ✅ | **阶段 0 的主力格式**，支持 VP8 / VP8L / VP8+VP8L 三种编码与 ANMF 动画 |
| PNG | `image/png` | `.png` | ❌（APNG 按静态处理） | 走 `ImageHeaderParser` |
| JPEG | `image/jpeg` | `.jpg` `.jpeg` | ❌ | 同上 |
| GIF | `image/gif` | `.gif` | ✅ | 同上 |

**扩展名只用于初筛，真实格式一律以 magic bytes 为准确认**（`ImageFormatSniffer.sniff`）：

| 格式 | 判定依据 |
|---|---|
| PNG | 前 8 字节 `89 50 4E 47 0D 0A 1A 0A` |
| WebP | 前 4 字节 ASCII `RIFF` **且** 偏移 8 起 4 字节 `WEBP` |
| JPEG | 前 3 字节 `FF D8 FF` |
| GIF | 前 6 字节 `GIF87a` 或 `GIF89a` |

若真实格式与扩展名不符（例如把 WebP 改名成 `.png` 想绕过校验），导入会以 `FailureKind.formatMismatch`（疑似伪造扩展名）**拒绝该文件并记录原因**，而不是静默接受。

## 3. 命名规则（`AssetFilenameParser`）

默认格式：**`角色名_情绪名_可选序号.扩展名`**

| 规则 | 说明 |
|---|---|
| 角色名 | **第一个下划线之前**的内容 |
| 变体序号 | **末尾**一整段纯数字（支持前导零，如 `01`）。只取最后一段，因此 `Angry_2_1` 的变体是 `1`、情绪是 `Angry_2` |
| 情绪名 | 中间**所有**部分的组合，**允许包含下划线**（`Bench_Thinking` 是一个情绪，不是两个） |
| 无序号 | 变体记为 `default` |
| 作品包名 | 取自**所在文件夹名** |
| 空片段 | 自动丢弃（`Maya__Angry` → 情绪 `Angry`，不会产生空情绪名） |
| BOM / 空白 | 自动剥离（Windows 下常见） |
| 扩展名 | 统一转小写 |

**规范化存储名**：`<Character>_<Emotion>_<variant>.<ext>`；无序号的文件**保持无序号**（不强行补 `_default`），保证重复扫描同一批文件时托管文件名稳定、不会往返漂移。

### 反例说明

| 文件名 | 角色 | 情绪 | 变体 |
|---|---|---|---|
| `Maya_Angry_1.webp` | Maya | Angry | 1 |
| `Maya_Bench_Thinking_1.webp` | Maya | Bench_Thinking | 1 |
| `Maya_Nod.webp` | Maya | Nod | default |
| `Maya_Worried.webp` | Maya | Worried | default |
| `Nod.webp` | Nod | default | default |

## 4. 资源上限（`AssetLimits`）

全部为**硬上限**，超限即拒绝该文件（不影响同批其他文件）：

| 项目 | 上限 | 常量 |
|---|---|---|
| 单文件体积 | 64 MiB | `maxFileBytes` |
| 单边尺寸 | 16384 px | `maxEdge` |
| 总像素 | 64 MP | `maxPixels` |
| 单文件帧数 | 2048 | `maxFrames` |
| ZIP 条目数 | 4096 | `maxZipEntries` |
| ZIP 单条目解压后 | 64 MiB | `maxZipEntryBytes` |
| ZIP 解压总量 | 512 MiB | `maxZipTotalBytes` |
| ZIP 压缩比 | 200 : 1 | `maxZipRatio` |
| 解码缓存条目 | 24 | `decodedCacheEntries` |
| 解码缓存字节 | 192 MiB | `decodedCacheBytes` |

后两项是为了**给渲染侧兜底**：解码后的位图走有限 LRU，绝不无限缓存全部素材。

## 5. 校验流水线

```
文件
 ├─ 0. 存在性 / 体积 / 空文件检查
 ├─ 1. ImageFormatSniffer.sniff()        只看文件头，不解码像素
 ├─ 2. format.isSupported ?               不支持 → unsupportedExtension
 ├─ 3. extensionMatches() ?               不符 → formatMismatch
 ├─ 4. SHA-256                            用于去重与「文件是否变化」判断
 ├─ 5. 容器头解析
 │     WebP → WebpContainerParser.parse() 尺寸/帧数/循环/时长/透明/编码/帧矩形
 │     其他 → ImageHeaderParser.parse()
 ├─ 6. 上限检查 _checkLimits()
 └─ 7. 真正解码一次（导入时）
        失败 → undecodable（标记校验失败，不写入托管目录）
```

**校验器契约：绝不抛异常**（`AssetValidator.probe` 的文档约定）。任何意外都被转成 `Err<AssetProbe>`，因此一个坏文件绝不会中断整批导入。

校验结果写入 `emotion_assets.validation_status`（`valid` / 其他）与 `validation_error`，素材库页面直接展示。

## 6. 失败原因分类（`FailureKind`）

| 取值 | 含义 |
|---|---|
| `unsupportedExtension` | 扩展名不在允许列表 |
| `formatMismatch` | 真实格式与扩展名不符（伪造扩展名） |
| `undecodable` | 无法解码（容器损坏 / 像素数据损坏） |
| `dimensionTooLarge` | 单边超限 |
| `tooManyPixels` | 像素总量超限 |
| `fileTooLarge` | 文件体积超限 |
| `tooManyFrames` | 帧数超限 |
| `unreadable` | 文件不存在 / 无权限 / 占用 |
| `unsafeArchive` | ZIP 安全校验未通过（路径穿越、zip bomb） |
| `emptyContent` | 无有效内容 |
| `unknown` | 未归类 |

批量导入返回 `BatchResult`：**成功项 + 失败项（含路径与原因）分别返回**，UI 与日志逐条列出损坏文件。

## 7. 导入流程（文件夹）

`DefaultAssetImporter._importFolder`：

```
1. FolderScanner.scan()                 递归/非递归列举，按扩展名初筛，文件数上限保护
2. 逐文件 AssetFilenameParser.parsePath()  文件夹名 → 作品包名
3. validator.probe()                     §5 的校验流水线
4. decoder 真正解码一次                  确认可渲染
5. 复制到托管目录：
     <AppData>/PetLife/assets/<ownerId>/<packSlug>/<characterSlug>/<规范化文件名>
   —— 用户原始文件全程只读
6. 写库：character_packs / character_models / emotion_assets
     UNIQUE(character_id, emotion_name, variant_name) + file_hash 去重
7. seedMappingsFor()                    按「建议情绪表」生成默认状态映射
8. 汇总 ImportReport（成功 N / 失败 M / 逐条原因）
```

**去重语义**：同一个 `(角色, 情绪, 变体)` 已存在时，比对 `file_hash`。相同则跳过；不同则**覆盖托管副本并更新库记录**（视为同一素材的新版本），不产生重复行。

## 8. ZIP 导入（`ZipAssetImporter`）

在前面的流程之外增加安全闸门：

| 检查 | 失败结果 |
|---|---|
| 条目数 > 4096 | `unsafeArchive` |
| 条目名含路径穿越（`..`、绝对路径） | `unsafeArchive` |
| 单条目解压后 > 64 MiB | `unsafeArchive` |
| 解压总量 > 512 MiB 或压缩比 > 200:1（zip bomb） | `unsafeArchive` |
| 条目内规范化文件名冲突 | 跳过并记 warning |

ZIP 之后交给同一个 `DefaultAssetImporter.ingestBytes()`，所以**校验规则只有一套**，不会出现「文件夹导入严格、ZIP 导入宽松」的裂缝。

## 9. WebP 容器解析要点

`WebpContainerParser` 是纯 Dart 的 RIFF/WEBP 解析器（与 `tools/webp_probe.py` 使用同一套规则，便于交叉验证）。

| 关注点 | 处理 |
|---|---|
| 编码类型 | 从 `VP8 ` / `VP8L` / `VP8X` 块推断，输出 `VP8 (lossy)` / `VP8L (lossless)` / `VP8+VP8L` |
| 动画 | 存在 `ANIM` + `ANMF` 块即视为动画；逐帧累计时长得 `animation_duration_ms` |
| 循环次数 | `ANIM` 块的循环字段（`0` 表示无限循环） |
| 透明通道 | 由 `VP8X` 的 alpha 标志或 `VP8L` 头推断 |
| **帧矩形** | 记录首帧矩形是否小于画布（`hasSubRectFrames`） |

**帧矩形是这套素材最容易踩的坑**：实测 13 个文件的 `ANMF` 帧矩形都**小于画布**，即每帧是带偏移的子矩形而非整幅画面。如果自己手写合成而忽略「帧矩形 + 混合/处置标志」，画面会错位或缺块。

本项目的处理方式：**把合成交给 Skia**（libwebp 的动画解码器返回的是**合成后的整幅画布帧**），同时把 `frame_count` / `animation_duration_ms` / `has_alpha` 写进数据库，并在导入日志中打印 `subRect=` 标记，便于日后排查显示问题。
