# 双端统计口径 P1 修复交付说明

本轮只处理审计建议的前三项 P1，未改 P2（跨窗口舍入守恒、Android 短会话规则、Windows 切换状态机细节）。

## 1. Android 进行中会话并入统计

修复前：Flutter 只导入**已结束**的 journal 会话，正在使用的应用不会出现在排行/时间线，可能连续几小时统计为 0。

修复后：

- `PetOverlayBridge.getCurrentUsageSession` 通过 Flutter 桥接暴露为 `AndroidOverlayPet.currentUsageSession()`。
- `AndroidUsageImportService.currentLiveSegment()` 把它转成 `LiveUsageSegment`，只读、不写库、不写 outbox。
- `UsageAnalyticsService` 接受可选的 `liveSegmentProvider`，在 `summarize()` / `timeline()` 中把当前会话临时并入：
  - 排行、分类、应用总时长、首末活跃时间都包含它；
  - 时间线显示为「使用中」，结束时刻取快照时刻；
  - 与已落库记录按确定性 segment ID 去重，会话结束导入后不会重复；
  - 窗口跨界仍按原有比例裁剪。
- 非 Android 平台 provider 为 null，行为完全不变。

## 2. 云端时间线统一为有效秒数

修复前：应用排行用 `active_seconds`，时间线用会话墙钟区间并集，出现「明细比总计大」。

修复后：`get_timeline()` 的每条展示项改用 `_effective_seconds(group)`，与 summary/apps 共用同一套「活跃秒数 + 重叠去重」口径。`started_at` / `ended_at` 仍保留真实墙钟起止，只修正时长。

## 3. 服务端时间不变量

新增校验：

```text
0 <= active_seconds <= ended_at - started_at
ended_at >= started_at
```

`ended_at < started_at` 仍在服务层按**单条记录**拒绝，避免一条坏数据让整批 422。新增的 `active_seconds` 超跨度同样走 `rejected[]` 的 `invalid_time_range`，不影响同批合法记录。

文档同步更新：`docs/18-数据同步协议.md`。
