## 一、诊断结论（D 系列实测）

**关键前提事实**：`WheelAnimationTimeline.openMs = 300`；生产顺序是
`prepareContent → setInteractive(true) → [异步 Region apply] → beginOpenAnimation()`，
而 `beginOpenAnimation` 之后 Widget 才挂载、`Ticker` 才启动 ——
**"点桌宠 → 真正可交互"实测约 400~500ms**，与你说的"约 0.5 秒"吻合。

| 用例 | 实测 | 结论 |
| --- | --- | --- |
| D1 悬停在 `opening` 期间 | `preview=null`（被丢） | `hover()` 开头 `if (state.phase.transitioning) return;` 把**整个打开动画期间的悬停全部丢弃** |
| D2 动画结束后（鼠标没动） | `phase=open preview=null sel=0 active=0` | 动画结束**没有任何**"按最近鼠标位置重算 hover" → 高亮回落 `selectedIndex = 0` |
| D3 动画**结束后**再悬停 + 推进时钟/多次 tick | `preview=3` 稳定不动 | **排除**"动画完成回调把选择重置"这类写法：没有任何地方写 `selectedIndex = 0` |
| D4 静止单击（down+up 同点、无 move） | `confirmed=[root_records]` | 装配层的静止单击**本身是好的** |
| D7 `opening` 期间 down、动画结束后才 up | `confirmed=[] closeRequests=0`，全程 `owner=none` | **down 被整条丢弃 → up 从 `_Owner.none` 求值 → `none`：这次点击被完全吞掉** |
| D8 动画前 / 后轮盘 Region 覆盖按钮中心 | before `21 块、6/6 覆盖`，after `27 块、6/6` | **排除**"Region 没跟上" |
| **D9 Region 内各分区的分布** | `rimOuterPx=293`、`ringRadius=252`；Region 内采样点 **ring=15521 / center=7278 / outside=21094**；死区最远半径 **544.5px** | **← 现象 2 的真凶**：Region（按 C1.1 契约必须覆盖**全部会被绘制的像素**，含标签、文字带、刀刃、齿轮）**远大于可点击的环带**；落在这 21094 个点上的单击全部走 `outsideTap → onRequestClose()` → **菜单关闭但什么都没执行** |

### 三个确认的缺陷

1. **过渡期悬停被丢 + 四个时机都不主动重算 hover**
   → 鼠标明明停在按钮上，高亮却回落第一项（现象 1）。
2. **Region ≫ 可点击区，形成 21k 点级"点它就关菜单"的死区**
   → "拿不到当前按钮，只执行了轮盘外层的关闭逻辑"（现象 2 的主因）。
   —— 注意这与 §六 的规则相矛盾：§六 说"按下**菜单背景**：不执行按钮"、"按下**轮盘外透明区域**：关闭菜单"；
   而现在代码把"Region 内、环带外"的一切都当成"透明区域"去关闭，**而真正的 Region 之外根本收不到事件**。
3. **down 落在过渡窗口内会整条丢失，up 到达时无从属** → 该次点击被吞（D7）。

> 说明：你猜的 `onTap { if (hoveredIndex == null) closeWheel(); }` 在代码里**不存在**（D4/D5 证明静止单击能命中）。
> 现象 2 的真实链路是 D9 的 Region 死区 + D7 的丢 down。

## 二、§三 交互态拆分（新增 `lib/menu/wheel_pointer_state.dart`）

新增纯 Dart 类 `WheelPointerState`，与 `WheelMenuStateMachine` 并列（**不混用一个索引**）：

```dart
class WheelPointerState {
  int? hoveredIndex;          // 鼠标悬停（Region 内真实 HitTest 结果）
  int? keyboardFocusedIndex;  // 键盘焦点（只有键盘输入后才参与视觉）
  int? gestureSelectedIndex;  // 圆弧滑选
  int? pressedIndex;          // 本次按下的按钮（PointerDown 实时 HitTest）
  PointerDeviceKind? activeInputKind;
  bool keyboardMode = false;
  Offset? lastPointerLocal;   // CanvasLocalSpace（唯一坐标口径）
}
```

视觉高亮**派生**，且**绝不由动画帧写入**：

```dart
int? get visualActiveIndex {
  if (keyboardMode) return keyboardFocusedIndex;
  return switch (activeInputKind) {
    PointerDeviceKind.mouse => pressedIndex ?? gestureSelectedIndex ?? hoveredIndex,
    PointerDeviceKind.touch => gestureSelectedIndex ?? pressedIndex ?? hoveredIndex,
    _                       => hoveredIndex,
  };
}
```

**无高亮 = `activeIndex = -1`**（`int` 语义不变，不动 painter 签名）：
`WheelRenderParams.activeIndex` 已是 `int`，`_drawButtons` 用 `slot.index == selected`、
`_drawTexts` 用 `>= 0` 判空 —— 传 `-1` 即"无任何按钮被高亮"，**零 painter 改动**。

## 三、§四 取消自动选中第一个按钮

* `prepareContent` / 打开完成 / `markOpened` / rebuild / `didUpdateWidget` / 换层动画收尾 /
  Region 提交完成 —— **一律不再**产生"高亮 = 第一项"。
* 打开完成时显式 `hoveredIndex = null; pressedIndex = null;`
  （`keyboardFocusedIndex` 可置 `firstEnabledIndex`，但**只有键盘输入后**才允许进入视觉）。
* `WheelMenuStateMachine.selectedIndex` **保留**，但语义收窄为"已确认项 / 弧形文字定位锚点"，
  **不再充当默认视觉高亮**。

## 四、§五 按下与抬起各自实时 HitTest

在 `PointerDownEvent` / `PointerUpEvent` 里用**事件当前坐标**重新命中：

```dart
final hit = hitTest(localPosition);          // 共享几何，唯一权威
down:  pressedIndex = hit?.index;
up:    final releasedHit = hitTest(localPosition);
       if (pressedIndex != null && releasedHit?.index == pressedIndex) confirmAction(pressedIndex!);
       else if (releasedHit?.isBackground == true) { /* 见决策 A */ }
       pressedIndex = null;
```

`hitTest` 返回 `WheelHit(index, zone)`；**禁止**用 `hoveredIndex` 代按下状态。

## 五、§六 事件所有权 + 不再抢按钮点击（含 D9 死区）

正式轮盘**统一由顶层 `Listener` 用共享几何分发**（`MouseRegion` 只负责 hover，不参与命中判定），
`IgnorePointer` 仍按 phase 控制整层是否入命中测试。分区规则（**按 §六 逐条**）：

| 分区 | 判据 | 按下 + 抬起同区 |
| --- | --- | --- |
| 按钮命中区 | 环带 **或 该按钮的标签/文字 chip**（见决策 B） | 执行按钮（§六-1） |
| 按下按钮、抬起按钮外 | — | 取消，**不执行、不关闭**（§六-2） |
| 菜单背景 | Region 内、非按钮、非缺口 | **不执行按钮**（§六-3）；是否关闭见**决策 A** |
| 中央缺口（桌宠） | 椭圆判定 | 未拖动 = 关闭（既有语义，保留） |
| Region 之外 | 收不到事件 | —（真正的"透明区域"，由外层处理） |

外层（pet tap / shell）**不得**再次消费同一次点击；动作执行后是否关闭**由动作结果协议决定**（§六-5/6）。

## 六、§七 四个时机主动重算 hover

维护 `lastPointerLocal`（**CanvasLocalSpace**；若只有屏幕坐标，必须经当前 `WheelSpaceSnapshot` 换算，
**禁止混用**），在下列时机各重算一次：

1. Region 已开放；2. 第一帧可见；3. 打开动画结束；4. 菜单层级切换完成。

```dart
hoveredIndex = lastPointerLocal == null ? null : hitTest(lastPointerLocal!)?.index;
```

**不得**在重算里默认第一项。

## 七、§八 换层清理

进/出子菜单：清 `hoveredIndex` / `pressedIndex` → 更新层级几何 → 用 `lastPointerLocal` 对**新几何**重算 hover；
鼠标正落在新按钮上则立即高亮；不在按钮上则**无高亮**；"返回"不得自动成为鼠标选择。

wheel.hit.down / wheel.hit.up / wheel.animation.completed / wheel.items.changed /

## 十二、需要你拍板的 3 个决策

**决策 A — Region 内、环带外、非缺口（即"菜单背景"）的单击该做什么？**
（这是现象 2 的正面；现状是"直接关菜单"，正是 bug。）
* A1（推荐）：**什么都不做**（不关、不执行）—— 最贴合 §六-3，也最不容易误关；
  关闭只保留"点中央缺口 / Esc / 动作协议 / 外层"。
* A2：**取消当前预览/滑选**（第二次点背景才关闭）。
* A3：**保持关闭**，但把 Region **可见性**与**命中区**拆成两套（Region 只负责画得出来，
  另算一套命中矩形）—— 改动最大，且要重新验证 C1.1/C1.1.1 的"标签不被硬裁"结论，**不推荐**。

**决策 B — 鼠标停在按钮的**标签 / 文字 chip**上时，算不算在选这个按钮？**
* B1（推荐）：**算**。把按钮命中区从"环带角度槽位"扩展为"环带 ∪ 该按钮的标签/文字 chip"。
  这既解决"移入按钮却高亮第一项"的直观 bug，也让 D9 死区大幅缩小。
* B2：不算（严格保持 Android 的环带判定）—— 则标签带仍是死区，只能靠决策 A 兜底不关菜单。

**决策 C — 视觉上接受"鼠标不在按钮上时**没有**任何按钮高亮"吗？**
（§四/§八 的字面要求；现在是"始终高亮第一项"。弧形文字与标题仍按 `selectedIndex` 排布，不受影响。）
* C1（推荐）：接受，按需求做。
* C2：保留"始终有默认高亮"，只取消"动画完成时重置"。
