# 04 · 桌宠窗口与配置持久化

## 1. 窗口初始化

`WindowsWindowController.initialize()`（`lib/desktop_window/windows_window_controller.dart`）：

```dart
await windowManager.ensureInitialized();
await windowManager.waitUntilReadyToShow(options, () async {
  await windowManager.setAsFrameless();     // 无边框
  await windowManager.setResizable(false);  // 桌宠形态不可缩放（面板形态会临时打开）
  await windowManager.setHasShadow(false);  // 去掉方框阴影，透明窗口才干净
  await windowManager.setPreventClose(true);// 点关闭按钮 → 隐藏到托盘，而不是退出
  await windowManager.show();
});
windowManager.addListener(this);
```

初始尺寸按「素材尺寸 × 缩放」计算，占位图阶段为 **512×384**（256×192 × 2.0）。

## 2. 窗口能力清单

| 需求能力 | 实现位置 | 说明 |
|---|---|---|
| 透明背景 | `MaterialType.transparency` + `setHasShadow(false)` | 立绘之外完全透明 |
| 无边框 | `setAsFrameless()` | 面板形态自绘 46px 拖拽条 |
| 置顶 | `setAlwaysOnTop(settings.alwaysOnTop)` | 默认开启 |
| 可拖动 | `PetView` 的 `onPanStart` → `windowManager.startDragging()` | 见 §3 |
| 位置锁定 | `PetView.onPanStart == null`（**Dart 侧生效**） | 见 §4 |
| 缩放 1×/2×/3×/4× | `scale` 参与「素材尺寸 × scale」计算 | 只允许整数倍，`normalized()` 强制取整 |
| 平滑 / 最近邻 | `FilterQuality.none`（默认，像素画清晰）/ `FilterQuality.medium` | 验收第 9 项：放大后不发虚 |
| 整体透明度 | `Opacity` widget（0.2 ~ 1.0） | Dart 侧合成，避免依赖平台透明度通道 |
| 鼠标穿透 | `setIgnoreMouseEvents(bool, forward: true)` | `forward: true` 保证穿透后事件继续下传 |
| 多显示器 | `DisplayTopology` + `moveTo()` 的位置夹取 | 见 §5 |
| 系统托盘 | `TrayService` | 见 §6 |
| 配置持久化 | `local_settings` 表 + `SqliteSettingsRepository` | 见 §7 |
| 面板形态 | `AppShell` 切到 1180×760、可缩放、强制关闭穿透与锁定 | 见 `01-架构说明与模块地图.md` §6 |

## 3. 拖动

`PetView` 的 `GestureDetector.onPanStart` 调用 `windowManager.startDragging()`，由系统接管拖动 —— 这比自己在 Dart 侧累加位移更跟手，也不会有拖出屏幕边界时的抖动。

面板形态的拖动由顶部 46px 拖拽条的 `onPanStart` 承担（同样走 `startDragging`，失败只记 `fine` 日志）。

## 4. 位置锁定为什么在 Dart 侧

`window_manager` 0.5.2 的 **Dart API 暴露了 `setMovable`，但 Windows 端 C++ 插件从未注册该方法**。调用它会抛：

```
MissingPluginException(No implementation found for method setMovable on channel window_manager)
```

如果这个异常发生在启动路径上，会把整个装配流程带崩。因此：

1. **移除**了 `applySettings` 里的 `setMovable` 调用；
2. 位置锁定改由 **Dart 侧强制执行**——`onPanStart: widget.lockPosition ? null : ...`。锁定时光标也从 `grab` 变成 `basic`，用户能直接感知到不可拖动；
3. `applySettings` 里每个平台调用都包了 `_try(label, op)`：

```dart
Future<void> _try(String label, Future<void> Function() op) async {
  try {
    await op();
  } catch (e, st) {
    Loggers.window.warning('窗口操作 $label 失败（已忽略，功能降级）', e, st);
  }
}
```

这样**单个平台能力的缺口永远不会中断启动**，只会让那一项功能降级并留下日志。

## 5. 多显示器兼容

`DisplayTopology.load()` 读取所有显示器与主显示器，并**把 `screen_retriever` 的依赖限制在这一个文件里**（阶段 4 换实现时其它代码不用动）。

每个显示器记录**可见区域**（`visiblePosition` + `visibleSize`）而不仅是分辨率：部分驱动（例如远程会话）下这两个字段可能为 null，此时退化为「整块屏幕都可见」。

**核心问题是「找不回来」**：用户在副屏放好桌宠后拔掉副屏，下次启动窗口会落在屏幕外，用户既看不到也点不到。处理方式 `DisplayTopology.clamp()`：

```
1. 检查窗口矩形与任一显示器的重叠面积是否 ≥ 48×48 px
2. 是 → 位置合法，原样保留
3. 否 → 重置到主显示器右下角（右下 − 窗口尺寸 − 24px），
        并 clamp 到主显示器范围内，同时记 warning 日志
```

首次启动（无保存位置）时 `_moveToDefaultCorner` 把窗口放到主显示器右下角（右 − 宽 − 32，下 − 高 − 96，给任务栏留位置）。

## 6. 系统托盘

`TrayService` 提供 4 个动作，全部通过回调注入，避免托盘模块反向依赖窗口/引擎：

| 动作 | 行为 |
|---|---|
| 显示 / 隐藏桌宠 | 读 `isVisible()` 后取反 `setVisible()` |
| 控制面板 | `AppServices.panelToggleHook` → `AppShell.togglePanel()` |
| 重置位置 | `moveTo(0, 0)` |
| 退出 | `AppServices.exitHook` → `AppShell._exitApp()` |

托盘图标的解析顺序（`AppServices.resolveTrayIconPath`）：

```
1. <exe 同级>/data/flutter_assets/assets/tray_icon.ico   ← 打包后
2. <AppData>/PetLife/assets/tray_icon.ico                 ← 开发期
3. 兜底相对路径 'assets/tray_icon.ico'
```

找不到图标只会让托盘初始化失败，**不影响桌宠本体**。

`onWindowClose`（点窗口关闭按钮）因为 `setPreventClose(true)` 生效，走的是「隐藏到系统托盘」而不是退出，日志：`收到窗口关闭请求，隐藏到系统托盘`。

**退出是一个显式动作**（托盘菜单 / 面板右上角电源按钮），顺序为：`setPreventClose(false)` → `shutdown()`（保存配置 + 释放资源）→ `destroy()`。`destroy()` 必须在 `shutdown()` 之后，否则窗口先没了、后续的平台调用会失败。

## 7. 配置持久化

所有配置存在 `local_settings` 表的 `(owner_id, key)` → `value` 键值对里（`AppSettings.toKeyValues()`），**不新增表、不新增字段，加配置项零迁移成本**。

| key | 类型 | 默认值 | 含义 |
|---|---|---|---|
| `window.alwaysOnTop` | 0/1 | `1` | 置顶 |
| `window.ignoreMouseEvents` | 0/1 | `0` | 鼠标穿透 |
| `window.lockPosition` | 0/1 | `0` | 锁定位置 |
| `window.scale` | double | `2.0` | 缩放倍数（取整到 1~4） |
| `window.smoothScaling` | 0/1 | `0` | `0` = 最近邻 |
| `window.opacity` | double | `1.0` | 整体透明度（0.2 ~ 1.0） |
| `window.crossFadeMs` | int | `220` | 淡入淡出时长（150 ~ 300） |
| `window.loopAnimation` | 0/1 | `1` | 动态图循环 |
| `window.x` / `window.y` | double? | 空 | 上次窗口位置 |
| `behavior.hideOnFullscreen` | 0/1 | `0` | 全屏时隐藏（阶段 1 生效） |
| `behavior.launchAtStartup` | 0/1 | `0` | 开机自启的**用户意图**（系统实况另见下） |
| `character.defaultCharacterId` | string? | 空 | 默认角色 |
| `character.defaultAssetId` | string? | 空 | 默认表情 |
| `state.lastCharacterId` | string? | 空 | 上次角色（重启恢复） |
| `state.lastState` | wireName | `default` | 上次状态（重启恢复） |
| `state.lastAssetId` | string? | 空 | 上次素材 |
| `state.manualAssetId` | string? | 空 | manual 临时锁定的图片 |

**读取容错**：`fromKeyValues` 对每个字段都做类型兜底（解析失败即回默认值），最后统一走 `normalized()` 把数值夹到合法区间。因此**手工改数据库或旧版本留下异常值都不会让应用崩溃**。

**开机自启是"两个真相"**：上表里的 `behavior.launchAtStartup` 只是**用户意图**，
真正生效的是 Windows 注册表
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `PetLife` 值。
设置页的开关渲染的是**注册表实况**（不是这张表），启动时还会按意图修复注册表路径。
完整设计见 [30-开机自启.md](30-开机自启.md)。

**恢复时机**：`AppShell._bootstrapAsync()` 在启动时读 `state.lastCharacterId ?? character.defaultCharacterId` 并 `stateEngine.start()`；若存在 `state.manualAssetId` 则一并 `lockManual()` 恢复手动锁定。退出时 `AppServices.shutdown()` 把自己的位置与当前角色/状态/素材写回（验收第 18 项）。
